# 实施与验证

规划器按可独立验收的结果确定负责人。拆分支撑节点时，要求明确下游会依据其产物做什么决定或操作。同一状态的连续修改尽量归同一节点，以减少重复操作和交接时的上下文丢失。

交付节点需要从原始要求和相关资料中提取验收条件，检查最终文件或回读实际状态。上游遗漏的要求也在验收范围内。发现问题时局部修正并复核，重试有副作用的操作前先确认已生效的变更。

规划器在节点说明中写明强制交付约束的依据，保留用户或适用资料明确规定的范围和排除项。拆分验收检查时保留原意和格式，让执行者在建议的方法与原要求冲突时调整方法。

回归用例位于 `tests/unit_tests/symphony/test_expert_task_planning.py`，覆盖规划请求中的指令、校验补试时保留的请求上下文，以及交付任务和交接产物在最终图中的投影。模型使用测试替身，真实任务得分需通过对照实验验证。

## 2026-11-26 上下文划分与内联角色

自动路由先判断哪些工作需要共享原始资料、判断过程与状态，再根据上下文隔离、并行价值、专业判断或独立复核决定委派。允许委派且目录没有合适专家时，可通过内联角色形成任务图。

专家成图将围绕相同上下文的取证、判断、执行、自检和修订归给同一负责人。图的任务节点用于派发，归主智能体负责的汇总和交付留在图外。独立专家说明判断职责、证据、工作准则和产物，交接只连接实际消费的具名产物。

在 Core `dda23abe2` 上用 DeepSeek-V4.1-Flash-1017 MAX 验证本次采用的提示词。五个合成任务走自动路由，共用状态的用例另测显式专家入口。并行核验图从三个节点减到两个。空专家目录下，日志取证、重识别风险判断和独立复核分别生成一个内联节点。共享状态用例在自动路由下由主智能体处理，显式专家入口把顺序操作合在一个节点。五张图均在一次校验补试后通过。此次实验只执行路由和图规划。
