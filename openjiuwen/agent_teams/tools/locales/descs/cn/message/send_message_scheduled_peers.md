向 Leader、其他成员或用户发送消息。用于同步需要 Leader 知道或决定的事项、升级阻塞问题、请求改派任务，以及与其他成员直接对接上下游细节。完成情况由任务的 `summary` / `note` 交接，**不要**用本工具汇报完成或送审。

本团队运行在**调度指派模式**，并开启了**成员间通信**：任务仍由 Leader 指派、调度框架交接，但你可以直接联系其他成员协调工作。

| 参数 | 含义 |
|---|---|
| `to="leader"` | 向 Leader 汇报（点对点）。这是**角色名**，不是具体成员名——系统会自动投递给真正的 Leader。需要它知道或决定的事项、阻塞、改派请求都发给它 |
| `to=<成员名称>` | 点对点消息（私聊）— 仅你与该成员可见。用于向上下游成员澄清接口、索取或确认产物细节等**协作沟通**；不要借此替别人分派任务或绕过 Leader 改动任务归属 |
| `targets=["m1","m2"]` | 多播 — 同一份内容分别发给每个成员，开销随接收人数线性增长，仅在确实需要部分成员同步看到同一内容时使用。数组内可以写 `"leader"`，不能包含 `"*"`/`"user"`；接收人恰好覆盖全体其他成员时必须改用广播。部分失败时返回值会列出已送达和失败的成员，不要对已送达的成员重发 |
| `to="*"` | 广播给所有成员 — **一次广播会唤醒每一个成员各跑一轮 LLM 交互，开销与团队规模成正比，务必慎用**，仅用于所有人都必须知晓的事项 |
| `to="user"` | 当收到的消息来源（`from`）为 `user` 时，必须用本工具把答复发回 `user` —— 你的普通文本输出不会送达用户 |

`to` 与 `targets` 必须且只能填写一个；多播数组必须直接放在 `targets`，不要把数组 JSON 编码成字符串塞进 `to`。发给尚未开工或正在休眠的成员时，消息会留在它的邮箱里，等它下次开工时一并读到。

你的普通文本输出对 Leader、其他成员和用户都不可见 —— 要通信必须调用此工具。来自 Leader 和其他成员的消息会自动送达，无需轮询。用名称称呼成员，不要使用内部 ID。
