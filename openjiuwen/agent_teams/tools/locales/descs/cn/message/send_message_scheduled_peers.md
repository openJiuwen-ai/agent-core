向 Leader、其他成员或用户发送消息。用于同步需要 Leader 知道或决定的事项、升级阻塞问题、请求改派任务，以及与其他成员直接对接上下游细节。完成情况由任务的 `summary` / `note` 交接，**不要**用本工具汇报完成或送审。

本团队运行在**调度指派模式**，并开启了**成员间通信**：任务仍由 Leader 指派、调度框架交接，但你可以直接联系其他成员协调工作。

| 参数 | 含义 |
|---|---|
| `to="leader"` | 向 Leader 汇报（点对点）。这是**角色名**，不是具体成员名——系统会自动投递给真正的 Leader。需要它知道或决定的事项、阻塞、改派请求都发给它 |
| `to=<成员名称>` | 点对点消息（私聊）— 仅你与该成员可见。用于向上下游成员澄清接口、索取或确认产物细节等**协作沟通**；不要借此替别人分派任务或绕过 Leader 改动任务归属 |
<!-- delivery:on -->
| `targets=["m1","m2"]` | 兼容旧调用的多播参数。普通集群 Agent 不使用；定向多人请拆成带 mode 的单独私信，全局变更可广播。 |
| `to="*"` | 登记团队广播。成员可接收、延后或丢弃。成功只确认广播已登记；关键成员必须确认时，向该成员单独发消息并请求回执。 |
<!-- delivery:else -->
| `targets=["m1","m2"]` | 多播 — 同一份内容分别发给每个成员，开销随接收人数线性增长，仅在确实需要部分成员同步看到同一内容时使用。数组内可以写 `"leader"`，不能包含 `"*"`/`"user"`；接收人恰好覆盖全体其他成员时必须改用广播。部分失败时返回值会列出已送达和失败的成员，不要对已送达的成员重发 |
| `to="*"` | 广播给所有成员 — **一次广播会唤醒每一个成员各跑一轮 LLM 交互，开销与团队规模成正比，务必慎用**，仅用于所有人都必须知晓的事项 |
<!-- delivery:end -->
| `to="user"` | 当收到的消息来源（`from`）为 `user` 时，必须用本工具把答复发回 `user` —— 你的普通文本输出不会送达用户 |

`to` 与 `targets` 必须且只能填写一个；多播数组必须直接放在 `targets`，不要把数组 JSON 编码成字符串塞进 `to`。发给尚未启动、正在休眠或出错的成员时，框架会把它拉起来处理这条消息；广播只拉起尚未启动的成员，不唤醒休眠成员。

## 普通集群私信：按信息的用途选择模式

仅适用于普通集群中发给 Agent 的私信；发给 `user`、广播和群聊不填模式。每次私信显式填写 `mode`。代码接受省略只是兼容旧调用，不是当前 Agent 的调用方式。接收方空闲时直接投递，无需先查询忙闲。

发送前判断：**如果对方完成当前任务后才收到，会不会已经太晚？**按信息对工作的影响选择，不按“补充说明”“通知”等标题、语气、长度或对方是否忙碌选择。

- **`steer`：当前任务结束前需要知道。**延后可能导致错误、返工、继续阻塞、使用旧接口，或使信息失去用途时使用。包括需求/验收标准变更、当前结果纠正、依赖产物已就绪、当前使用的接口/样例澄清，以及开始工作前的必要指导。它在下一次模型决策前提供上下文，不强行停止当前工具，也不要求接收方推倒重做。例：“你正在写的文档中，修正样例第 5 行编号已变更，请按新文件说明。”
- **`follow_up`：独立的后续请求。**只有对方完全不知道这条消息也能正确完成当前任务，并且消息在当前任务结束后仍有处理价值时使用。例：“当前报告完成后，再另做一份英文摘要。”不能把当前所需信息延后；不要为了“不打扰忙碌成员”而选择它，也不要依赖未来某条 steer 来带入它。
- **`abort`：当前执行本身必须立即停止。**仅 Leader 可用；不能等下一次模型决策再纠正时才使用。一般需求变更、补充信息和普通返工用 steer，不因暂时无回复而 abort。它直接停止执行并清空 follow_up，正文不执行，已发生的修改不回滚；仅 Leader 后续的新私信才能恢复。不要把“停止并汇报”写在同一条 abort 中；确需恢复或交接时另发新私信，礼貌确认不应解除停止。普通成员用 steer 向 Leader 提出停止申请、说明原因，由 Leader 判断。

一条消息同时含当前纠正与独立后续请求时，尽量拆开并分别选模式；确需合发时用 steer，正文明确各部分时机。不能把消息被提前带入上下文当作后续任务应立即执行。无法确定是否影响当前任务、且延后可能造成错误或返工时，用 steer；不要为选模式反复查询进度。已通过任务看板交接的完成结果不重复发，无需行动的感谢或确认不发。

在本工具允许的收件人范围内，定向多人时分别用 `to=<成员名>` 发送并逐个选择模式；不要用 targets 绕过选择，包括 targets 只有一个人的情况。工具保留 targets 仅为兼容旧调用。全局变更仍可使用 `to="*"` 广播，不填发送方模式，由接收方决定。
