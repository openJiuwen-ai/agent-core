把你**正在执行**的任务拆成子任务，交给自己或其他成员完成。

适合的场景：当前任务里有几块能并行、或能独立交付的工作，交给别人（或先由你自己集中做完一块）比在一个任务里串行推进更合适。只是需要一点协助时，不必拆任务，直接沟通即可。

## 调用后会发生什么

1. 子任务落库，每个子任务归属你指定的 `assignee`；调度框架会按依赖自动开工并通知承担者
2. **你当前的任务立即挂起**（`blocked`），等全部子任务结束（完成或被取消）。挂起期间它不占你的名额，所以子任务也可以指派给你自己
3. 全部子任务结束后，调度框架重新开始你的任务，并以 Leader 消息通知你继续，消息里附带每个子任务的结果摘要；需要全文时用 `view_task(action='note', task_id=...)`

**调用成功后立即结束本轮**，不要继续推进被挂起的任务，也不要等待或轮询子任务——结果会自动送达。子任务不会单独通知 Leader，结果只回到你这里，由你汇总进自己任务的完成摘要。

## 任务字段

- **title**: 简明描述子任务目标
- **content**: 目标、验收标准和约束，写清你需要它交付什么、交付到哪里，便于你恢复后直接使用
- **assignee**（必填）: 已存在的智能体成员，可以是你自己；不能是 leader 或人类成员。需要新成员时请 Leader 安排
- **task_id**（可选）: 自定义 ID，用于子任务之间的依赖引用
- **depends_on**（可选）: 前置任务 ID 列表，可引用同批子任务或看板上已有任务

## 限制

- 只能拆你自己正在执行（`in_progress`）的任务；计划审批中或验收中的任务不能拆
- 子任务可以继续拆分，但层数受团队配置限制，超出时会报错，此时请自己完成或告知 Leader
- 不能给子任务配验证者，也不能修改已有任务的依赖
- 你不能修改或取消已创建的子任务；需要调整时告知 Leader
