## Running on a third-party CLI

The team declares third-party CLI agents (claudecode / codex / ...) in `TeamAgentSpec.external_cli_agents`. With `cli_agent` set, this teammate's brain is that CLI subprocess rather than a local LLM: the framework launches the CLI from the declared config, auto-injects the team collaboration tools (view_task / claim_task / send_message / ...), and pushes inbound messages to it directly, so it participates as a first-class member. `member_name` / `display_name` / `desc` / `prompt` mean the same as for a local teammate; `isolation` / `permissions` / `fork` / `fork_source` / `fork_mode` apply only to a local teammate and are rejected together with `cli_agent`.

Set `model_name` only when the user explicitly specifies it, and only to a team model pool endpoint compatible with the CLI's model API protocol; you must not choose, infer, or auto-fill a model from those available. When the user has not explicitly specified a model, omit the field so the third-party agent uses its own default model. `external_cli.fallback_model_name` must come from the team model pool and use a model API protocol compatible with the protocol supported by this third-party agent. Follow a fixed fallback priority: prefer the current model when it is present in the pool and its protocol is compatible; when the current model is absent from the pool or its protocol is incompatible, select another compatible model; omit the field when no compatible model exists or the cli_agent has no authentication fallback, so the member continues in native mode. Never invent a model merely to fill the field. When a compatible fallback is available, an explicit authentication failure switches to it and retries once only when the turn produced no output or tool side effects.

| Parameter | Visibility | Usage |
|---|---|---|
| **cli_agent** | internal | The CLI kind to launch (e.g. `claude` / `codex`); must match a static config entry pre-declared in `TeamAgentSpec.external_cli_agents` — the launch command, working directory and MCP injection all live in that entry, and this field only references it by name |
| **external_cli.fallback_model_name** | internal | Only valid for cli_agent kinds with an authentication fallback (those listed under `compatible_fallback_models`); for any other cli_agent it **must be omitted**. **Required** when that cli_agent has a compatible model; omit it when the pool contains no compatible model, explicitly selecting native mode without automatic fallback |
