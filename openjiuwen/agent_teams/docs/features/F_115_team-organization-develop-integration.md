# Team Organization 合入 develop

## 元信息

| 项 | 值 |
|---|---|
| 日期 | 2026-10-07 |
| 范围 | Organization、Team Runtime/Tools、ReAct 工具增量装配、使用指南 |
| 关联 spec | `S_29_team-organization.md` |

## 背景

联调分支与 develop 已存在较大差异。直接采用联调分支版本会覆盖 develop 新增的
运行时生命周期、harness、工具命名空间和观测能力；本次在 develop 上移植组织能力，
冲突点保留现有入口语义，并在其上增加组织绑定和协作。

## 决策

- Team 内协作与 Organization 跨团队协作分层：不替换原有 TeamRuntimePool、成员调度或普通团队工具。
- 工作空间 Git 初始化使用既有互斥锁串行化；组织目录的阻塞文件检查放到工作线程。
- SQLModel 查询使用 `col()` 表达数据库列，明确查询类型而不改变状态转换逻辑。
- 保留 develop 的模型配置、提示词加载、观测 rail 和 stop 清理行为，组织释放只补充关联清理。
- 与 Swarm 联调时，实验配置仅控制 Organization 前端入口；SDK 不设置全局后端禁用开关。
- 中英文用户文档分主题提供使用说明，不生成自动 API 文档。

## 拒绝的方案

- 用旧分支文件整体覆盖 develop：会丢失已合入的运行时能力。
- 为全部 Team 增加强制组织初始化：破坏原有团队的独立运行方式。
- 宣称现有消息抽象已经支持分布式组织：当前组织运行时仍依赖进程内 Leader 与共享 TeamDB。
- 同时修改 Swarm 本地依赖锁定：本地联调改动不属于此次功能合入；配套 SDK 依赖升级应独立评审。

## 验证

Organization 的数据库、任务、消息、汇总、专家适配、工作空间与超时生命周期均有单元测试。
同时运行 Runtime、团队工具、提示词加载和 ReAct 回归；完整测试结果见 PR 的验证记录。
未运行真实模型端到端测试，不将单元测试通过等同于产品验收完成。

## 已知边界

组织跨进程传输、跨节点运行及恢复能力不在本次范围。Swarm 必须使用配套 SDK 版本才能使用新能力；
其默认关闭的 UI 开关不负责升级依赖。后续真实模型联调按 Swarm 使用指南验收。
