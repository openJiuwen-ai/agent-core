# Summary Submission Closeout

## 元信息

| 项 | 值 |

| 范围 | `organization/runtime.py`、双语收尾模板 |

## 背景

汇总已形成草稿，但 Leader 在普通协作轮返回后没有调用 `org_summary_complete`。
仅增加收尾提示仍会让模型执行 shell、搜索错误目录或重复派发任务，并再次耗尽迭代预算。
阻塞通知读取了 `OrgTaskCreator` 不存在的 `leader_id`，导致收尾异常进入整轮重排队路径。

## 决策

- 同一运行时、同一执行最多一次自然暂停后的提交补偿，不修改旧任务数据或根任务领取规则。
- 补偿轮使用 request-local ContextVar，覆盖宿主激活与其异步 Agent 调用，并在退出时恢复。
  绑定时只为 Summary Leader 挂载 `_SummaryCloseoutRail`；正常协作轮和 Teammate 不受该工具集合限制。
  作用域辅助函数与独立 Rail 类集中在 `runtime.py`，作为内部实现，不新增公共导出。
- 模型窗口只披露 `read_file`、`org_summary_get_inputs`、`org_summary_complete`；
  工具执行入口再次拒绝其他工具，先于权限确认，防止旧上下文工具调用绕过披露过滤。
- 收尾模板包含当前成员真实工作区路径。正文通过正式提交写入任务，不强制提供可选文件 URI。
- 阻塞通知发往根任务 assignment，消息服务解析其已注册 Leader；通知异常只记日志，
  不重新执行 Summary。收件通知触发用户可见的 Root 交付轮，报告阻塞而非宣称完成。
- 前端切换入口独立于附件菜单；组件卸载保留缓存，真正删除会话才清理。
  Owner 空闲时仍进行可见页面轮询，并响应会话相关事件。

## 拒绝的方案

- 自动将草稿文件认作成功：不能证明内容符合要求，也绕过正式提交。
- 增加迭代次数或无限重试：不能消除错误工具路径与重复研究。
- 创建者自动认领根任务：创建者不一定具备最合适的能力，本次不改变领取机制。

## 成员迭代耗尽补充修复

2026-10-08 联调发现 delivery-drafter 在第 12 轮仍在读写和统计字数，没有交回草稿。
内部草稿任务未结束会阻止整个 Team 暂停，因此仅等待自然暂停的补偿不能覆盖该路径。
宿主仅对 Summary 错误帧调用运行时通知：第一次通过已有内部消息通道唤醒 Leader，
同一错误帧去重，再失败向根任务认领者报告阻塞，不自动重放模型输入。
Leader 初稿交接与定向修订合计最多两次，提交成功使用现有 force-finish 结束当前 Turn。
Summary Spec 继承宿主有限预算，缺省或非法值回退 200；仍保留一次提交补偿，普通 Team 不变。
拒绝无限重试、单纯提高上限和把磁盘草稿自动当作正式成果。
