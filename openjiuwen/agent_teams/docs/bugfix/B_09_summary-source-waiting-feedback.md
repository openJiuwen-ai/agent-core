# Summary 来源待验收时误提示 Owner 结束回合等待

## 元信息

| 项 | 值 |
|---|---|
| 日期 | 2026-10-26 |
| 范围 | Organization 聚合规则、任务池只读诊断与工具反馈 |
| 关联 spec | S_29_team-organization.md |

## 现象与根因

Owner 验收外团来源后遗漏本团贡献的验收，三个子任务虽已 COMPLETED，但一个来源仍 PENDING。
Summary 正确停留 WAITING_SOURCES，创建工具却无条件发布已委派进度并要求 Owner 结束回合等待。
工具还可能返回绑定前的旧状态，导致来源已就绪时返回值与真实调度不一致。
实际日志中补充验收后立即启动汇总，证实阻塞发生在来源门槛，而非 Summary 内部执行。

## 决策

- 按最新任务和执行状态生成返回值与进度，等待时列出持久化绑定中未就绪的必需来源。
- 复用现有 COMPLETED + ACCEPTED 判断，只返回状态与验收责任团队，不读取来源正文或扩大快照权限。
- 明确本团贡献仍需显式验收；运行中的执行继续沿用原有等待交付与调度方式。
- 中英文共享聚合规则明确：不存在承担完整根交付的专业团队，且各团提供并列独立领域结论时，必须采用 SUMMARY_TEAM；内容大小、节约时间、开销、冲突或 Owner 自行整理均不能改变判断。HIERARCHICAL 仅适用于专业团队交付完整根成果；aggregation_mode 参数说明同步强调这两个条件。

### 本团组织子任务的执行状态

本团成员已完成工作时，组织子任务可能仍显示 DELEGATED，因为 Leader 未先启动并回写成果。
澄清组织工具同样管理本团承担的组织任务；协作提示词要求在执行或内部派发前 start，成员完成后检查并及时 complete，再显式验收。
仅补充中英文行为指引与工具说明，不把内部完成事件自动映射成组织完成，不改变运行时状态机。

## 拒绝的方案

- 自动接受本团贡献或跳过验收：会降低既有完成门槛。
- 禁止提前创建 Summary：会破坏已有等待来源与后续自动启动能力。
- 新增轮询、重试调度或前端补偿：问题在工具反馈，现有验收后的唤醒路径可正常工作。

## 验证

回归覆盖本团来源未完成、待验收、拒绝、需修订与已验收状态；重复创建读取持久化绑定，
显式验收后执行转为 RUNNING，并保留正常启动调度。旧绑定快照用例验证返回最新状态。
真实模型遵循聚合提示词的效果仍需实际场景验证。
