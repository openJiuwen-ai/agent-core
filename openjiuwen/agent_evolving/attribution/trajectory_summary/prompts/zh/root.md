# Root：面向不同读者的两种总结

针对同一选区的执行轨迹，在同一次 report_summary 调用中返回 narrative、display_summary 和更新后的 problems。

narrative 将保存为 trajectory_summary，供后续诊断归因使用。综合目标、关键决策与操作、跨主体交接、实质结果、恢复过程、验证证据和剩余问题，可保留少量输入已有的短节点定位。正文与问题状态保持一致，不重列每个主体的时间流水或参数表。

display_summary 面向用户总结执行过程，不能只写最终结果或照抄 narrative。说明要做什么、主要经过哪些阶段、如何分工协作（如有），以及实际验证了什么、交付了什么。用自然、简洁的句子或短段落，按操作目的描述过程，不写内部 ID、节点或块编号、审批流水、工具调用清单及脚本实现细节。仅补充有证据支持、影响目标达成或交付可信度的重要缺口；轻微且已恢复的噪声省略，无明确缺口时不强行添加。

两种总结均须保留不确定性，区分回报完成与实际成功。
