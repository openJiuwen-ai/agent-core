# Events 开发与文档维护规范

本目录维护 Core 的事件机制实现及其设计、规约、特性记录和开发计划。
通用开发与文档要求采用 [Core 公共规范](../AGENTS.md)，本文仅补充模块职责和维护入口；
当前行为通过实现与测试核实，已确认契约由主责规约维护。两者不一致时，按
[Core 同步流程](../AGENTS.md#特性设计与契约同步)处理，并区分目标设计与已实现能力。

## 适用范围与规则入口

- 本文适用于 `openjiuwen/core/events/` 及其全部子目录。先遵循
  [仓库根规则](../../../AGENTS.md)和 [Core 公共规范](../AGENTS.md)，再执行本模块补充要求。
- 本模块负责事件类型与 Handler 的注册、匹配、分发、执行链控制及相关公共契约。
  业务模块负责在真实业务入口触发事件，并实现所属业务的默认处理逻辑。
- EventHandlerOps、Builder 和会话上下文的归属与依赖方向见
  [详细架构第 3.2 节](docs/designs/events-architecture.md#32-代码归属与依赖方向)。该文档仍为目标设计草案，
  待确认事项保留相应标识；跨模块修改检查提供方与调用方，避免将业务实现直接耦合进事件基础设施。
- 当前目标方案从本模块的设计概览和详细架构进入；正式规约建立后，已确认契约在主责 spec 中唯一维护，
  概览与架构引用该位置。设计中的示意代码不代表最终接口或已实现能力。
- 修改前阅读已有实现、公开导出、调用方、相关测试和模块设计，核对本次变化的实际影响。

## 模板与必要内容

模板与填写要求采用 [Core 模板与必要内容要求](../AGENTS.md#模板与必要内容)，模板在
[公共模板目录](../docs/templates/)统一维护。

## 开发与文档同步

设计先于实现、契约同步及验证记录采用
[Core 同步流程](../AGENTS.md#特性设计与契约同步)。公共契约变化同步其主责文档，模块专属契约在
`docs/specs/` 维护，具体方案和实施记录在 `docs/features/` 维护。

实现中需要调整已确认架构时，说明修改内容、原因、影响及验证方式，按已有授权和适用规则更新设计；
仅修正过时事实或引用时按公共同步规则处理。不将目标设计或参考示例直接写成当前实现事实。

## 引用与交付检查

提交及公共交付检查采用 [Core 交付要求](../AGENTS.md#引用与交付检查)，模块重点检查如下：

- 检查文档相对路径、章节锚点及引用方，保持本模块设计入口有效。
- 核对概览、架构、spec、feature 和开发计划中的名称、职责、范围、依赖、状态及证据是否一致。
- 实现变化按 [Core 测试要求](../AGENTS.md#测试与验证)验证，重点覆盖受影响的注册、匹配、执行顺序、
  短路、错误和隔离行为；只记录实际执行的验证及其限制。
- 纯文档修改检查内容、链接和差异，无需运行业务测试。运行 `git diff --check`，
  并单独检查该命令不覆盖的未跟踪新文件。
