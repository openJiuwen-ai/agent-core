# F_20 ReAct 迭代耗尽后的结构化结果

## 元信息

| 项 | 值 |
|---|---|
| 日期 | 2026-10-11 |
| 范围 | ReActAgent、RSI 结果消费者、BrowserService |
| 测试基线 | ReAct / RSI / Browser / DeepAgent 关联测试；模型协议与真实模型试跑 |
| Refs | GitHub agent-core #1847 / GitCode agent-core #2013 |

## 背景

工具循环耗尽预算后只返回固定英文错误，调用方无法获得已采集证据，也无法稳定区分
模型错误与迭代上限。Browser 等消费者依赖该英文字面量，改变显示语言会丢失原因。

## 数据结构与状态

ReActAgentConfig 增加 `on_max_iterations`：`error`（默认）、`return_observations`、
`final_answer`。预算耗尽统一附带 `termination_reason`、`iterations_used` 与
`truncated_by_max_iterations`。后两种策略返回当前轮可用的工具观察；恢复中断时保留
同一用户轮次的证据，不混入更早用户轮次。已被压缩删除的证据无法重建。

`final_answer` 在工具循环结束后发起一次逻辑模型调用，不提供工具。空白、工具请求、
截断、过滤、模型失败或仍需继续的结果回退为带证据的错误。取消向上传播，rail 的显式
结束或中断优先。框架原有模型/上下文恢复可能重试该调用，工具不会再次执行。

## 决策

- 默认策略保持旧错误正文、结果类型和上下文保存次数，仅增加结构化字段。
- BrowserService 保留 worker 的结构化结束原因，即使正文可解析为 JSON；兼容旧结果。
- RSI 的判断逻辑兼容结构化原因及旧文本，不改其既有评估/恢复策略。
- 部分回答仍带耗尽标记；DeepAgent 外层任务循环与 TaskCompletionRail 不据此自动完成任务。
- 流式文本先于最终状态到达，调用方必须检查最后的结构化结果。

## 拒绝的方案

- 默认额外调用模型：会改变既有成本和时延，因此仅显式选择 `final_answer` 才启用。
- 允许收尾再执行工具：无法保证迭代预算边界。
- 只用错误文案判断：无法支持本地化或新的返回正文。
- 将观察结果直接标为成功：原任务可能仍未完成。

## 验证

单元测试覆盖三种策略、公开 stream()、异常/取消、rail 中断/继续、用户新输入、工作流
重放、上下文恢复重试和消费者兼容性。HTTP 与真实模型试跑覆盖三种策略的 invoke/stream。
宿主调用方仍须区分 `result_type` 与 `termination_reason`，不能把部分答案当作完成证明。

## 已知遗留

本变更不为 DeepAgent 增加新的外层配置项；其内层 ReAct 默认行为与外层预算语义不变。
模型可能在有限证据上作答不准确；本策略提供预算终止信息，不保证答案语义正确。
