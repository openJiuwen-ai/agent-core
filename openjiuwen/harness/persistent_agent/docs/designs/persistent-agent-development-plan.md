## 1. 怎么读这份计划

Persistent Agent 接收一次已经确定归属的任务，在对应会话中运行 Agent，并把执行过程和结果交还给调用方。本模块提供运行对象的构造入口及会话内隔离能力；**AgentServer 决定何时、为哪个 Session 创建实例**，并负责实例调度。同一业务 Agent 可以拥有多个 Session；一个运行实例在同一时刻只处理一个 Session，并行的 Session 使用不同实例。业务 Agent 的身份创建、配置发布、会话排队、群内模型调用额度管理、管理查询、定时计划的创建与触发、结果投递和产品页面均属 AgentServer 等其他层，不列入本清单。定时触发已形成的普通任务可由本模块执行。

每行只回答三件事：**做什么、怎样证明做成、开工前必须完成什么**。验收场景可以先用模拟调用方和模拟存储验证；“完成”仍需留下测试或联调证据。“开工硬前置”只列缺少它就无法独立实现当前特性的本模块能力，不把最终联调所需的所有特性都列为开工条件。可并行启动时间和联调汇合点见第 3 节。当前特性 ID 为 `PA-01`～`PA-20`；之前的编号均未进入实现，以本版清单为准。DeepAgent 已有的任务循环、模型与工具调用、流式输出和子代理能力优先复用；本计划只列 Persistent Agent 必需的会话适配与可靠交接。

本文使用的几个词：

| 词 | 在本文中的意思 |
| --- | --- |
| Session（会话） | 一段独立的对话或工作；不同 Session 不共享未完成任务和私有记录 |
| Request（请求） | Session 中的一次具体任务；中断后要继续原 Request |
| 运行实例 | AgentServer 通过本模块构造入口为一次活动调用创建的 Persistent Agent/DeepAgent 执行对象、工具和控制状态；实例只接受指定 Session，用完后清理 |
| Window（窗口） | 当前送给模型的工作上下文；内容太多时要保存旧窗并切换新窗 |
| Checkpoint（恢复点） | 已确认、可读取的任务状态快照，用于故障后继续 |
| 宿主端口 | 调用方提供的事件确认、权限、预算、存储等接口；本计划只实现 Persistent Agent 对这些接口的使用 |

状态使用“待开始、进行中、阻塞、待验收、完成”。“完成”须有对应验收证据；仅写了代码但没有完成验证时标“待验收”。

## 2. 要开发的特性

### A. 能创建、能执行一次任务

| ID | 特性：要做什么 | 怎样证明做成 | 开工硬前置 | 状态 | 负责人 | 证据 |
| --- | --- | --- | --- | --- | --- | --- |
| PA-01 | 定义一次调用需要哪些信息和接口 | 缺身份、权限或必需接口时得到明确错误；接口超时不会被当作“没有数据” | 无 | 待开始 | 待分配 | — |
| PA-02 | 提供 Persistent Agent 运行对象的构造入口 | 调用方传入有效配置可创建对象；缺少必需能力时创建失败；构造本身不运行任务 | PA-01 | 待开始 | 待分配 | — |
| PA-03 | 固定实例的 Session 归属并隔离内部状态 | 实例接收指定 Session 的调用后，消息、工具上下文、取消信号和清理范围只归该 Session；向活动实例传入另一 Session 会报错，不会读写原 Session 的状态 | PA-02 | 待开始 | 待分配 | — |
| PA-04 | 复用 DeepAgent 执行指定任务并回传过程与结果 | 私聊或定时任务可完成或明确失败，纯文件结果可返回引用；复用 DeepAgent 的任务循环与流式输出，将执行进度、工具调用和结果转成带稳定编号的统一事件；接收方暂不可用时暂停依赖步骤，恢复后核对已确认事件 | PA-02 | 待开始 | 待分配 | — |
| PA-05 | 为模型准备本次需要的上下文 | 判断、执行和恢复各拿到适当资料；最终输入超出模型容量时停止调用并说明原因 | PA-01 | 待开始 | 待分配 | — |
| PA-06 | 判断是否参与一条群消息 | 对普通消息和 @ 消息都能给出“忽略、回复、介入”之一；私聊任务不经过这一步 | PA-01 | 待开始 | 待分配 | — |
| PA-07 | 交接 Agent 响应和文件结果 | 群聊回复与其他回复从同一事件出口返回；文件只保存在办公空间时不算群内可见。要让群内人类或其他 Agent 感知，结果须注明目标群、文件引用及“上传群空间”或“发到群内”的共享方式，交由调用方按权限投递；重复交接不产生重复消息或文件 | PA-01 | 待开始 | 待分配 | — |
| PA-08 | 响应停止、取消、审批和补充信息 | 停止只影响目标任务；审批只用于对应操作且只生效一次；新任务不会插入当前任务 | PA-01 | 待开始 | 待分配 | — |

PA-02 只验证构造入口；PA-03 验证实例内部的归属校验与状态隔离；PA-04 验证 DeepAgent 执行结果到统一事件出口的完整链路。PA-04 不重写 DeepAgent 的任务循环或另建一套流式输出；稳定业务事件编号、提交确认和结果未知时的核对仍由 Persistent Agent 适配。AgentServer 负责调用构造入口、为并行 Session 分配不同实例并管理实例生命周期；PA-03 不实现这些调度工作。群内模型调用额度由 AgentServer 管理，本模块仅遵守宿主准入结果并回传实际用量，不维护预算账户。

### B. 能记住工作内容并读取资料

| ID | 特性：要做什么 | 怎样证明做成 | 开工硬前置 | 状态 | 负责人 | 证据 |

| PA-09 | 保存当前上下文窗口 | 首次调用只创建一个窗口；再次保存能找到最新内容；保存回复丢失时能查出是否已保存 | PA-01 | 待开始 | 待分配 | — |
| PA-10 | 窗口满时继续工作 | 旧内容保存并可回查后创建并启用新窗口；新窗口一旦生效，后续事件提交或执行失败仍以新窗口为活动窗口，恢复时不切回旧窗口 | PA-09 | 待开始 | 待分配 | — |

| PA-12 | 读取 PersonalContext 知识 | 同一次模型调用使用同一版知识；知识更新或撤权后，下次调用不再使用失效内容 | PA-01 | 待开始 | 待分配 | — |
| PA-13 | 读取办公空间文件 | 能列出和读取当前授权范围内的文件；越界路径、其他 Session 的私有目录被拒绝 | PA-01 | 待开始 | 待分配 | — |
| PA-14 | 安全地调用有写入效果的工具 | 写入前记录本次操作；结果不明时查询原操作，不直接重做 | PA-01 | 待开始 | 待分配 | — |
| PA-15 | 直接修改办公空间文件 | 能按授权创建和修改文件；两个任务同时改同一文件、写入回执丢失时能核对实际结果 | PA-13、PA-14 | 待开始 | 待分配 | — |

文件只读与写入分开：PA-13 可以先交付；PA-15 在写操作可核对后再启用。Agent 直接在办公空间读写文件。PA-12 只负责使用 PersonalContext 已提供的知识，其采集和发布由 PersonalContext 负责。

## 3. 开发计划

以下按**交付节点和并行工作线**组织开发，不排具体日期或工期。节点表示可以交付、演示和验收的结果；工作线表示可以交给不同开发者同时推进的工作。某项工作一旦满足第 2 节的开工硬前置就可以启动，不必等同批其他工作结束。

### 3.1 先交付接口基线

| 节点 | 开发内容 | 交付与放行标准 |
| --- | --- | --- |
| M0：接口基线 | PA-01；确定调用输入、事件与确认、权限、控制、存储等最小契约，并准备模拟调用方和模拟端口 | 无效输入、接口超时和结果未知均有明确语义；各工作线能依据同一契约独立实现和测试。PA-01 完成后启动下表全部工作线 |

### 3.2 并行开发工作线

| 工作线 | M0 后立即做 | 本线后续安排 | 向哪个节点交付 |
| --- | --- | --- | --- |
| A：实例与执行 | PA-02 构造入口 | PA-02 完成后，PA-03 实例隔离和 PA-04 DeepAgent 执行适配并行开发；两者就绪后合并验证 | M1：一次指定 Session 的任务能运行并返回结果 |
| B：上下文与交互 | PA-05 上下文、PA-06 群消息判断、PA-07 响应交接、PA-08 控制信号可分别开发 | PA-05、PA-07、PA-08 随 A 线汇入 M1；PA-06 随群消息场景汇入 M2a | M1、M2a |
| C：窗口、检索与恢复 | PA-09 窗口保存、PA-11 历史检索、PA-12 知识读取可并行开发 | PA-09 完成后并行做 PA-10 换窗与 PA-16 恢复点；PA-16 完成后做 PA-17 原 Request 恢复 | M2a：长上下文；M2c：中断恢复 |
| D：办公空间 | PA-13 文件读取与 PA-14 写操作核对并行开发 | 两项都完成后做 PA-15 文件修改 | M2b：办公空间读写 |
| E：学习 | PA-18 学习目标识别 | PA-18 完成后并行做 PA-19 处理结果跟踪和 PA-20 反馈调整 | M2d：主动学习，独立交付 |

每条线先用 M0 的模拟端口完成本线特性验证。A 线优先保证 M1 可运行，B～E 线同时开发；C 线的 PA-17 和 D 线的 PA-15 分别等待本线必要能力完成，不等待其他整条工作线。若人手不足，优先安排 A、B 线完成 M1，并同时保证 C 线的 PA-09、D 线的 PA-14 有负责人，以免后续恢复与文件写入成为长尾；E 线可独立推进。

### 3.3 按可交付结果逐个汇合

| 节点 | 汇合时机与参与特性 | 必须演示并留下的验收证据 |
| --- | --- | --- |
| M1：可执行任务 | A 线的 PA-02～PA-04，与 B 线的 PA-05、PA-07、PA-08 就绪后汇合 | 指定 Session 的任务可以执行、停止和返回结果；错误与结果丢失后能核对；实例拒绝另一 Session 的输入 |
| M2a：群消息与长上下文 | M1 可运行后，汇入 PA-06、PA-09～PA-12；这些特性可以在 M1 前独立完成 | 群消息判断与普通响应链路配合；窗口切换、历史分页、知识版本与撤权有可复现结果。群文件共享交接同时验证 PA-07 |
| M2b：办公空间读写 | M1 可运行后，汇入 PA-13～PA-15；与 M2a 并行验收 | 授权读写成功，越界访问被拒绝；并发修改和回执丢失时核对真实结果，不重复写入 |
| M2c：中断后继续原任务 | PA-09、PA-10、PA-14、PA-16、PA-17 与 M1 的执行链就绪后汇合；可与 M2a、M2b 交叉推进 | 保存失败不覆盖旧恢复点；重启后沿原 Request 和已确认事件继续；等待中的控制信号及写操作结果被正确核对。M2c 完成前，还须在 M2b 就绪后验证涉及文件写入的恢复场景 |
| M2d：主动学习 | E 线 PA-18～PA-20 完成后独立汇合，无须等待 M1～M2c | 仅从授权记录创建目标；处理批次和反馈可追溯；处理失败不显示为知识更新 |

M2a、M2b、M2c、M2d 不是彼此的阶段门，满足各自汇合条件即可验收。AgentServer、PersonalContext 和办公空间只提供本模块所需的接口与验证环境，它们自身的开发不在本计划内。对端尚未就绪时先用模拟端口留下模块验证证据，真实对端联调作为对应节点的待验收项跟踪。详细故障场景见[架构设计的 V01～V41 验证矩阵](persistent-agent-architecture.md)；这些节点目前均未完成。
