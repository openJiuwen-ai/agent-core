## 1. 怎么读这份计划

Persistent Agent 接收一次已经确定归属的任务，在对应会话中运行 Agent，并把执行过程和结果交还给调用方。本模块提供运行对象的构造入口及会话内隔离能力；**AgentServer 决定何时、为哪个 Session 创建实例**，并负责实例调度。同一业务 Agent 可以拥有多个 Session；一个运行实例在同一时刻只处理一个 Session，并行的 Session 使用不同实例。业务 Agent 的身份创建、配置发布、会话排队、群内模型调用额度管理、管理查询、定时计划的创建与触发、结果投递和产品页面均属 AgentServer 等其他层，不列入本清单。定时触发已形成的普通任务可由本模块执行。

**本期目标：支持指定 Session 内持续执行、上下文保存与换窗、历史检索、知识使用和结果交接；暂不实现执行进程中断后重建现场并继续原任务。** 本文是[完整目标架构](persistent-agent-architecture.md)的分期交付计划，不改变后续恢复能力的目标契约；架构中涉及恢复的要求按第 3.4 节分类验收，不能把本期通过视为完整架构已实现。

- 正常请求结束后，后续请求可读取同一 Session 已保存的上下文；新 Session 不自动继承其私有窗口和未完成工作。
- 当前运行对象仍存在时，可以停止、取消、等待审批或接收匹配的补充信息；释放对象后重建等待现场属于后续中断恢复。
- 本期的“核对”指当前调用内查询保存、提交、换窗或工具操作的实际结果；接口暂时恢复可继续核对，不代表进程退出后能续跑原任务。
- 进程异常退出后，已保存历史和已提交事实保留，未完成请求交宿主明确处置；本模块不自动重跑，也不把读取历史当成恢复原请求或跳过其队列位置的依据。
- DeepAgent 的构造、任务循环、模型与工具调用、流式输出、基础控制、状态序列化和子代理运行时作为复用基础；AgentServer 提供调度、授权、预算、权威提交确认和投递。本模块实现上下文管理及这些能力的执行侧适配。

每行只回答三件事：**做什么、怎样证明做成、开工前必须完成什么**。验收场景可以先用模拟调用方和模拟存储验证；“完成”仍需留下测试或联调证据。“开工硬前置”只列缺少它就无法独立实现当前特性的本模块能力，不把最终联调所需的所有特性都列为开工条件。可并行启动时间和联调汇合点见第 3 节。当前特性 ID 为 `PA-01`～`PA-21`，保留原 PA-01～PA-20 编号；历史变更记录中的旧编号不用于当前认领。PA-21 单列跨资料来源的失效管理，避免重复建设知识读取或通用上下文引擎。

本文使用的几个词：

| 词 | 在本文中的意思 |
| --- | --- |
| Session（会话） | 一段独立的对话或工作；不同 Session 不共享未完成任务和私有记录 |
| Request（请求） | Session 中的一次具体任务；本期不重建中断任务，后续恢复必须关联原 Request |
| 运行实例 | AgentServer 通过本模块构造入口为一次活动调用创建的 Persistent Agent/DeepAgent 执行对象、工具和控制状态；实例只接受指定 Session，用完后清理 |
| Window（窗口） | 当前送给模型的工作上下文；内容太多时要保存旧窗并切换新窗 |
| Checkpoint（恢复点） | 已确认、可读取的任务状态快照，用于故障后继续；属于后续阶段 |
| 宿主端口 | 调用方提供的事件确认、权限、预算、存储等接口；本计划只实现 Persistent Agent 对这些接口的使用 |

状态使用“待开始、进行中、阻塞、待验收、完成”。“完成”须有对应验收证据；仅写了代码但没有完成验证时标“待验收”。交付分类与开发状态分别记录：第 2 节 A、B 组属于本期，C 组属于后续中断恢复，D 组属于独立学习扩展；未排入本期不等于阻塞或完成。

- 持久化等待、跨重启外部操作续跑及子代理现场重建等待 M2c；子代理基本执行可复用，写工具未通过父调用约束适配时禁用。
