# persistent_agent/docs

本目录维护 Persistent Agent 的通用执行契约、整体设计、特性记录和开发计划。
本文按 [Harness 公共文档规范](../../docs/AGENTS.md)的章节组织，通用要求引用相应章节，
并保留本模块的目录、职责、架构确认和具体计划入口；代码行为以实现和测试为准。

## 适用范围与规则入口

- 本目录采用 [公共文档规范](../../docs/AGENTS.md)。各节说明采用的公共要求及本模块补充，
  具体设计写入对应文档。
- Persistent Agent 负责 `agent-core` 中指定 Session 内的执行、调用状态隔离、上下文组装、
  窗口与归档、历史检索、办公空间访问和续做能力。
- AgentServer 的配置发布、渠道绑定、会话排队、单一执行者保证、候选结果接收与渠道投递
  在 `jiuwenswarm` 仓维护；跨仓接口在这里说明 Persistent Agent 一侧的输入、输出与约束，
  并标注对端文档或代码位置。
- [PersonalContext](../../personal_context/)负责知识采集与发布；这里记录获授权知识版本在
  Execution 开始及后续读取中的使用。DeepAgent、Rail、工具和工作空间的公共契约引用
  [Harness 公共规约](../../docs/specs/)，不在本目录复制定义。

## 命名与编号

文件命名、独立递增编号、历史编号保留及日期维护采用
[公共命名与编号规则](../../docs/AGENTS.md#命名与编号)。保留现有概览、架构和开发计划的文件名。

计划条目使用 `PA-NN`，feature 文件使用 `F_NN`，两者分别编号；在 feature 中标注关联
计划条目，在计划中链接对应方案，不默认编号相同。

## 模板与必要内容

阅读并参考相应模板。模板统一维护在[公共模板目录](../../docs/templates/)，本目录不另建模板表

接入缺口和实际验收边界；通用的 spec / feature 内容及验证证据要求采用公共规范。

## 开发与文档同步

设计先于实现、契约变化同步 spec / feature、过时事实修正及实际验证记录采用
[公共同步流程](../../docs/AGENTS.md#开发与文档同步)。公共契约变化同步其归属文档，
模块专属契约在本目录维护。

实现过程中需要改变已确认的[架构方案](designs/persistent-agent-architecture.md)时，先说明
修改内容、原因及对当前特性的影响，取得开发者确认后更新架构文档并按确认方案实现；
已有明确授权的调整按该授权执行。仅纠正过时事实或引用时按公共同步规则处理，
涉及方案变更时执行上述确认流程。
