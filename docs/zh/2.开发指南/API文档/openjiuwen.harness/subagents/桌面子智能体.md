# 桌面子智能体（cua_agent）

通过窗口截图和真实的鼠标键盘输入操作本机原生应用的桌面子智能体。

---

## 概述

`cua_agent` 操作真实的应用窗口：列出窗口、截取窗口截图，并在从截图上读取的像素位置点击、输入、
滚动和启动应用。需要支持视觉的模型。

输入是真实的前台输入：智能体会移动鼠标，并向当前拥有键盘焦点的位置输入，所以每个针对窗口的操作
都会先把该窗口置于前台。智能体工作时不要使用这台机器，或启用[用户接管暂停](#function-create_cua_agent)。
把鼠标移到屏幕角落会中止智能体的下一个操作。

网页不归本智能体处理，浏览器自动化由 [`browser_agent`](./浏览器子智能体.md) 负责。Discord、Slack、
VS Code 等 Electron 桌面应用是普通桌面窗口，由本智能体处理。

用 `create_cua_agent` 构建独立智能体，或用 `build_cua_agent_config` 注册为子智能体，由父智能体通过
`task_tool`（`subagent_type="cua_agent"`）委派。`DeepAgent` 也接受工厂名 `"desktop_agent"` 作为别名。

**平台**：Windows，以及带 X11 显示的 Linux（需设置 `DISPLAY`；不支持没有 X 的 Wayland）。智能体必须
运行在它所操作的交互式桌面会话中。

### 安装与配置

`uv sync --extra cua`（或 `pip install 'openjiuwen[cua]'`）安装桌面依赖：pyautogui、psutil，Windows 上
另有 pygetwindow，Linux 上另有 python-xlib。

| 环境变量 | 用途 |
|---|---|
| `OPENJIUWEN_SUBAGENT_TASK_TIMEOUT_S` | 单次 `task_tool` 委派的时长上限，对所有子智能体类型生效。默认 `720` |

第一次调用模型前，`CuaRuntimeRail` 检查桌面是否可用；缺少依赖、平台不支持或无法连接显示时，报错并
给出处理办法。

## function create_cua_agent

```python
create_cua_agent(
    model: Model,
    *,
    card: Optional[AgentCard] = None,
    system_prompt: Optional[str] = None,
    tools: Optional[List[Tool | ToolCard]] = None,
    mcps: Optional[List[McpServerConfig]] = None,
    subagents: Optional[List[SubAgentConfig | DeepAgent]] = None,
    rails: Optional[List[AgentRail]] = None,
    enable_task_loop: bool = False,
    max_iterations: int = 25,
    workspace: Optional[str | Workspace] = None,
    skills: Optional[List[str]] = None,
    backend: Optional[Any] = None,
    sys_operation: Optional[SysOperation] = None,
    language: Optional[str] = None,
    prompt_mode: Optional[str] = None,
    cua_capabilities: Optional[List[str]] = None,
    cua_instance_key: str = "",
    cua_snapshot_keep_last_k: int = 3,
    cua_pause_on_user_input: bool = False,
    **config_kwargs: Any,
) -> DeepAgent
```

创建桌面子智能体。所授予 capability 对应的[桌面工具](#桌面工具)和[内置 Rails](#内置-rails) 追加在调用方传入的
`tools` 和 `rails` 之后。

**参数**:

| 参数 | 类型 | 默认值 | 说明 |
|---|---|---|---|
| `model` | `Model` | *(必填)* | 支持视觉的模型实例 |
| `card` | `Optional[AgentCard]` | `None` | 智能体身份卡。为 None 时创建 `name="cua_agent"` 的默认卡 |
| `system_prompt` | `Optional[str]` | `None` | 替换默认提示词 |
| `max_iterations` | `int` | `25` | 最大迭代次数。每次操作后都要重新截图验证，低于约 20 时任务容易中途耗尽 |
| `language` | `Optional[str]` | `None` | `"cn"` 或 `"en"` |
| `cua_capabilities` | `Optional[List[str]]` | `None` | 授予的 capability，见 [Capability](#capability)。为 None 时授予 `input` 和 `app_lifecycle`；`core` 总是包含 |
| `cua_instance_key` | `str` | `""` | 为保持 API 稳定而保留，不产生作用：每个智能体都有自己的工具实例 |
| `cua_snapshot_keep_last_k` | `int` | `3` | 上下文中保留的最近截图结果与截图数，至少为 1。单窗口任务可设为 `1` 以节省上下文 |
| `cua_pause_on_user_input` | `bool` | `False` | 用户正在使用鼠标或键盘时暂缓桌面操作 |
| `**config_kwargs` | `Any` | — | 转发到 `create_deep_agent()`，例如 `permissions`、`permission_host`，见[权限](#权限) |

其余参数（`tools`、`mcps`、`subagents`、`rails`、`enable_task_loop`、`workspace`、`skills`、`backend`、
`sys_operation`、`prompt_mode`）原样传给 `create_deep_agent()`。

**返回值**: `DeepAgent` — 已配置的桌面子智能体。

**异常**: 以下情况抛 `ValueError`：未知的 capability 名称；`cua_snapshot_keep_last_k` 小于 1。

**示例**:

```python
from openjiuwen.core.runner import Runner
from openjiuwen.harness.subagents import create_cua_agent

agent = create_cua_agent(model, language="cn", cua_capabilities=[])  # 只读：仅 core

await Runner.start()
try:
    result = await Runner.run_agent(
        agent,
        {"query": "列出当前打开的应用窗口。", "conversation_id": "cua-demo"},
    )
finally:
    await Runner.stop()
```

## function build_cua_agent_config

```python
build_cua_agent_config(
    model: Model,
    *,
    card: Optional[AgentCard] = None,
    system_prompt: Optional[str] = None,
    tools: Optional[List[Tool | ToolCard]] = None,
    mcps: Optional[List[McpServerConfig]] = None,
    rails: Optional[List[AgentRail]] = None,
    enable_task_loop: bool = False,
    max_iterations: int = 25,
    workspace: Optional[str | Workspace] = None,
    skills: Optional[List[str]] = None,
    backend: Optional[Any] = None,
    sys_operation: Optional[SysOperation] = None,
    language: Optional[str] = None,
    prompt_mode: Optional[str] = None,
    cua_capabilities: Optional[List[str]] = None,
    cua_instance_key: str = "",
    cua_snapshot_keep_last_k: int = 3,
    cua_pause_on_user_input: bool = False,
    permissions: Optional[dict] = None,
    permission_host: Optional[Any] = None,
) -> SubAgentConfig
```

构建一个 `SubAgentConfig`，父智能体首次委派时用 `create_cua_agent` 实例化。参数在此时即校验，`ValueError`
的情形与 `create_cua_agent` 相同。

**参数**: 与 `create_cua_agent` 相同（不含 `subagents` 和 `**config_kwargs`），另有：

| 参数 | 类型 | 默认值 | 说明 |
|---|---|---|---|
| `permissions` | `Optional[dict]` | `None` | 子智能体的权限策略 |
| `permission_host` | `Optional[ToolPermissionHost]` | `None` | 应答权限确认的宿主，见[权限](#权限) |

**返回值**: `SubAgentConfig` — 子智能体配置，`factory_name="cua_agent"`。

**示例**:

```python
from openjiuwen.harness.factory import create_deep_agent
from openjiuwen.harness.subagents import build_browser_agent_config, build_cua_agent_config

coordinator = create_deep_agent(
    model=model,
    subagents=[
        build_cua_agent_config(model, language="cn"),
        build_browser_agent_config(model, language="cn"),
    ],
)
```

## 桌面工具

智能体调用 `get_window_state(pid, window_id)` 查看窗口：它把窗口置于前台，返回窗口边界和该窗口的截图。
对该窗口调用指针类工具时传入的每个 `x,y` 都是其最新截图中的像素，从截图左上角起算；不带 `pid` 时 `x,y`
为屏幕坐标。`zoom` 以原始分辨率截取一个区域，用于看清小字或图标；之后指针类工具传 `from_zoom=true`，
并使用从缩放图上读取的 `x,y`。

| 工具 | 作用 |
|---|---|
| `list_windows`、`list_apps` | 窗口（`window_id`、`pid`、`title`、`bounds`、`minimized`）及其所属应用 |
| `get_window_state` | 把窗口置于前台并返回其截图 |
| `zoom` | 以原始分辨率截取窗口的一个区域（四周自动留白） |
| `get_screen_size`、`get_cursor_position` | 显示器尺寸与光标位置（像素） |
| `click`、`double_click`、`right_click`、`move_cursor`、`drag`、`scroll` | 按窗口像素发送指针输入 |
| `type_text`、`press_key`、`hotkey` | 向窗口发送键盘输入；带 `x,y` 时先点击该输入框 |
| `launch_app`、`bring_to_front` | 启动应用（路径、可执行文件名、Windows 上的 `ms-settings:` 等 URI 或 AUMID）或把其窗口置于前台 |
| `kill_app` | 强制终止进程 |

回复以 `✅` 开头表示操作已执行；以 `❌` 开头表示无法执行，且没有发送任何输入。

## Capability

`cua_capabilities` 从固定目录（`openjiuwen.harness.tools.cua`）中选择工具。只构建选中的工具，模型看不到其他工具。

| Capability | 工具 | 默认授予 |
|---|---|---|
| `core` | `list_windows`、`list_apps`、`get_window_state`、`zoom`、`get_screen_size`、`get_cursor_position` | 总是 |
| `input` | `click`、`double_click`、`right_click`、`move_cursor`、`drag`、`scroll`、`type_text`、`press_key`、`hotkey` | 是 |
| `app_lifecycle` | `launch_app`、`bring_to_front` | 是 |
| `app_termination` | `kill_app` | 否 |

传 `[]` 得到只读智能体（仅 core）。

### function resolve_cua_capabilities

```python
resolve_cua_capabilities(
    requested_names: Optional[Iterable[str]],
    available_capabilities: Iterable[CuaCapability] = DEFAULT_CUA_CAPABILITIES,
) -> ResolvedCuaCapabilities
```

把 capability 名称展开为工具白名单。总是加入 `core`，去除重复；未知名称记入 `rejected_names`，不抛异常。
`rejected_names` 非空时，工厂函数抛 `ValueError`。

**返回值**: `ResolvedCuaCapabilities` — 不可变 dataclass，含 `requested_names`、`selected_names`、
`rejected_names` 和 `allowed_tool_names`。

## 内置 Rails

`create_cua_agent` 在调用方的 rails 之后追加以下 rails，它们只作用于桌面工具：

| Rail | 条件 | 作用 |
|---|---|---|
| `CuaRuntimeRail` | 总是 | 第一次调用模型前检查一次桌面是否可用 |
| `CuaRepeatFailureRail` | 总是 | 同一调用反复得到相同的非成功回复时，第 3 次附加建议，第 6 次拒绝该调用 |
| `CuaProgressRail` | 总是 | 汇报本次运行的进展（见下文） |
| `CuaScreenshotDownscaleRail` | 总是 | 把超出图像 token 预算的截图重新编码，并告诉模型缩放系数 |
| [`MultimodalContextSummarizerRail`](../rails/rails.md) | 总是 | 只保留最近 `cua_snapshot_keep_last_k` 张截图 |
| `CuaUserTakeoverRail` | `cua_pause_on_user_input=True` | 用户操作时暂缓动作，空闲 5 秒后继续，持续 60 秒仍在操作则停止并汇报 |
| `ContextProcessorRail` | `rails` 中未传入 `ContextProcessorRail` | 只保留最近 `cua_snapshot_keep_last_k` 个 `get_window_state` / `zoom` 结果，较早的结果转存到工作区并替换为简短预览 |

## 委派结果与续跑

父智能体通过 `task_tool` 委派时，`cua_agent` 结果的 `data` 包含：

| 字段 | 含义 |
|---|---|
| `output` | 子智能体的回答 |
| `resume_task_id` | 传回它即可继续同一个桌面会话 |
| `cua_result` | `CuaProgressRail` 写入的进展报告 |
| `retryable` | 除 `cua_result.status` 为 `"completed"` 外均为 `True` |
| `resume_context` | `status`、`blockers`、`current_window`、`recommended_recovery`、`resume_count` |

`cua_result.status` 为 `"completed"`、`"partial"`（有操作失败）或 `"blocked"`（重复失败的调用被拒绝）。
它是启发式判断，不代表任务一定成功。`blockers` 最多列出 5 个失败操作，格式为 `工具名: 错误首行`。

**超时**：`cua_agent` 委派在 `task_tool` 时长上限前 20 秒自行停止，返回成功结果，其中 `status="timeout"`、
`retryable=True`、`resume_context.last_action_confirmed=False`。桌面会话和已完成的步骤都会保留，但停止时
正在执行的操作可能已生效而未被记录。

**续跑**：再次调用 `task_tool`，传 `subagent_type="cua_agent"`、同一个 `resume_task_id`，以及只描述剩余
部分的 `task_description`。子智能体会收到上次的状态、窗口、blockers 和恢复提示，并被要求先重新截图再操作。
不传 `resume_task_id` 时，每次委派都开启新会话。

## 权限

传入 `permissions` 时，`create_cua_agent` 把以下规则加到该策略的副本中（不修改你的字典）：

| 规则 | 工具 | 决定 |
|---|---|---|
| `cua_desktop_force_terminate_app` | `kill_app` | 拒绝 |
| `cua_desktop_launch_app` | `launch_app` | 询问 |
| `cua_desktop_type_text` | `type_text` | 询问 |

即使你的策略允许所有操作、按名称允许 `kill_app` 或为它设置了审批覆盖，`kill_app` 仍被拒绝。不传
`permissions` 时，智能体不启用权限引擎。这些规则只作用于本智能体，其他智能体的同名工具（如 mobile_gui
的 `type_text`）不受影响。

会改变桌面状态的工具属于 `os_control` 类别。`pattern: "*"` 的 `os_control` 规则匹配该工具的每次调用；其他
pattern（精确、glob 或 `re:`）匹配调用参数 `text`、`name`、`bundle_id`、`value`、`key` 或 `keys`。

`kill_app` 被上述规则拒绝，因此默认不授予。请求 `app_termination` 即可授予，此时系统提示词会追加
「先尝试正常关闭应用」的指引。

在 `task_tool` 委派中，「询问」无法通过父对话到达用户。请传入 `permission_host`，由其
`request_permission_confirmation` 在进程内应答；或只使用允许和拒绝规则。

```python
permissions = {
    "enabled": True,
    "schema": "tiered_policy",
    "defaults": {"*": "allow"},
    "rules": [
        {
            "id": "deny_shell_launch",
            "tools": ["launch_app"],
            "match_type": "os_control",
            "pattern": "re:(?i)^(powershell|pwsh|cmd)(\\.exe)?$",
            "action": "deny",
            "severity": "CRITICAL",
        }
    ],
}
```

每条规则都要写明 `action`。只写 `severity` 不会让规则变成拒绝。
