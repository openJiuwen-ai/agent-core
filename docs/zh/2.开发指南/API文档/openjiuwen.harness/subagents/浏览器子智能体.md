## 总体架构

默认路径是浏览器子智能体直接使用 Playwright MCP 和本地辅助工具，不是每个工具再派发一个 LLM worker。

```text
JiuwenSwarm 主 Agent / Swarm 成员
  -> BrowserTaskPromptRail（宿主上的 SubagentRail 扩展）
  -> task_tool(subagent_type="browser_agent")
  -> 创建或复用子智能体，准备任务资源，绑定 child Session
  -> DeepAgent -> 内层 ReAct 模型与工具循环
       BrowserRuntimeRail：任务状态、动作校验、预算、证据、最终结果
       ContextProcessorRail：窗口裁剪、当前页面、工作上下文
       MCP primitives + Probe + Batch + browser_recall_offload
  -> BrowserAgentRuntime -> BrowserService / ActionController / PageState
  -> Playwright MCP stdio -> managed Chrome / remote CDP / extension
  -> authoritative_browser_result -> task_tool.browser_result -> 主 Agent
  -> 清理 observer、任务绑定和执行占用；按策略保留浏览器与 Profile
```

三种“状态”不能混为一谈：

| 状态 | 所有者 | 用途 |
|---|---|---|
| 浏览器进程、标签页、Cookie、Profile | 驱动或外部宿主 | 页面执行和登录持久化；可跨任务复用 |
| PageState、generation、目标注册表 | BrowserAgentRuntime | 当前页身份和可执行目标，旧目标不能跨导航直接复用 |
| query、证据、deadline、resume 次数、模型上下文 | 父/子 Session 与 runtime | 当前任务的完成和恢复，不因共享 Cookie 就共享任务记忆 |

## 创建与装配

### function create_browser_agent

模块：`openjiuwen.harness.subagents.browser_agent`。返回 `DeepAgent`。

```python
def create_browser_agent(
    model: Model,
    *,
    card=None,
    system_prompt=None,
    tools=None,
    mcps=None,
    subagents=None,
    rails=None,
    enable_task_loop=False,
    max_iterations=100,
    temperature=0.4,
    workspace=None,
    skills=None,
    backend=None,
    sys_operation=None,
    language=None,
    prompt_mode=None,
    settings=None,
    browser_key=None,
    browser_instance=None,
    browser_capabilities=None,
    **config_kwargs,
) -> DeepAgent:
    ...
```

以上省略参数类型，完整签名以[工厂源码][source-agent]为准。

1. 校验 capability 名称并展开 MCP 白名单；`None` 和 `[]` 都只选择 `core`。
2. 复制模型配置并设置浏览器温度，不修改父模型描述；温度限制在 0..2。
3. 解析 `RuntimeSettings`，构造 `BrowserAgentRuntime`。
4. 注入两个 Probe、Batch、offload recall。
5. 注入 `BrowserRuntimeRail` 和上下文 processors；已有 `ContextProcessorRail` 时向其追加 processors。
6. 通过 `create_deep_agent` 装配，不在工厂调用时启动 Chrome/MCP；在任务准备和首次调用时按需启动。
7. 注册 `acquire_task_resources` / `release_task_resources` 生命周期钩子。

调用方的 `tools` / `rails` 在构造列表中位于注入项之前，实际回调顺序还受 rail priority
和事件路由控制，不能把列表顺序当成完整执行顺序。
`skills` 是显式参数；主 Agent 加载某个 skill，不意味着浏览器子智能体自动获得同一 skill。
自定义 tools、mcps、rails、配置和宿主权限策略会改变最终工具面，本文默认清单不包含这些扩展。

### function build_browser_agent_config

同模块的配置工厂返回 `SubAgentConfig`，用于主 Agent 注册浏览器预设。
它接受与上面相同的模型、提示词、tools、mcps、rails、workspace、skills、backend、
sys_operation、language、prompt_mode、settings、browser_key、browser_instance 及迭代/温度参数，
但不接受 `subagents`、`browser_capabilities` 或任意 `**config_kwargs`。

它设置 `factory_name="browser_agent"` 并将已解析 settings 存入 `factory_kwargs`。
任务级 capability 由 `task_tool` / `SubagentRail` 在实际创建子智能体时传递，不应给这个配置工厂传一个不存在的参数。

### 配置优先级

- 显式 `settings` 原样优先使用；另传的 `browser_key` 或 `browser_instance` 不会自动覆盖其内部 instance/MCP 配置。
- 否则先使用传入 Model 的 client/request 配置，再构建浏览器 MCP 和 guardrails；
  不能从模型推导时才走环境配置构建。
- `browser_instance` 支持配置对象或 dict；`browser_key` 是 instance.key 的便捷入口。
- 任务 capability 必须为字符串列表；未知名称报错，不默默开放新工具。

## 完整工具清单

本节枚举当前 SDK 自带的浏览器工具，不把“代码中定义了”写成“默认注册给模型了”。
MCP 的实际参数 schema 和可用工具还取决于运行中的 Playwright MCP `tools/list`；
SDK capability 目录是允许范围，不负责凭空实现服务器未提供的工具。

### 默认注册范围

| 层 | 默认行为 |
|---|---|
| MCP 模型工具 | `core` 的 14 个名称与服务器实际工具的交集 |
| 本地模型工具 | `browser_probe_interactives`、`browser_probe_cards`、`browser_batch_interact`、`browser_recall_offload` |
| 可选 MCP 工具 | 任务显式选择 capability 后放行；宿主权限和图像支持仍可能收窄 |
| 管理/兼容 Tool 类 | 定义存在，但默认工厂不装配；不能仅添加 capability 来注册 |
| 内部代码执行 transport | Probe、页面状态采集、Batch 使用，不等于给模型开放代码执行 |

### Playwright MCP 工具

能力目录见 [browser_capabilities.py][source-capabilities]。下面是全部 11 个 capability 中的 69 个工具名称；
`advanced_code` 与 `unsafe_dev` 同时请求时保留后者、移除前者，因此不意味着一次调用会暴露全部 69 个。

`resolve_browser_capabilities(requested_names, available_capabilities=DEFAULT_BROWSER_CAPABILITIES)`
返回 `ResolvedBrowserCapabilities`，包含 requested_names、selected_names、rejected_names、
allowed_tool_names。解析器负责规范化、去重和展开，不自行理解任务来选择能力；
工厂发现 rejected_names 时抛出 ValueError。模型通常通过父 task_tool 的 browser_capabilities 提出选择。

### 不应误认为默认工具的项目

- `browser_wait_for` 不在当前受信 capability 目录内，即使 MCP 支持，也不是默认模型工具。
  有条件等待可使用 Batch 的 `wait_for_*` 操作；内部单步适配仍可能调用底层等待工具。
- `browser_progress` 不是注册工具；旧协议别名纠正只为兼容错误模型输出。
- `BrowserWorkingContextStore` 和 processors 是内部状态/上下文组件，不是模型工具。
- `build_playwright_mcp_config` 会启用 transport 所需的 MCP 扩展 caps；
  “MCP 服务器支持全部 caps”不等于“当前任务允许全部 caps”。
- runtime 内部优先使用 `browser_run_code_unsafe`，不可用时回退 `browser_run_code`。
  把这两者从底层 MCP 包装器彻底删除，会破坏 Probe、元数据采集及 Batch，
  不能通过删除内部 transport 来实现模型工具白名单。

## 运行时辅助工具参数

### tool browser_probe_interactives

默认本地工具。参数均可省略：

| 参数 | 默认/限制 | 含义 |
|---|---|---|
| `max_items` | 30，限制为 1..40 | 控件数量上限 |
| `viewport_only` | true | 只检查当前视口 |
| `query` | 空字符串 | 按文本/搜索别名筛选 |

返回紧凑 PageState、当前 `generation_id`、控件 `target_id`、role/text/region/kind、
可见性、可用性和匹配数。模型使用公开 target，不拼造内部 selector 或 Probe-local id。

### tool browser_probe_cards

默认本地工具。参数：`max_cards=12`（1..20）、`viewport_only=true`、
`include_buttons=true`、`query=""`。

适合重复搜索结果、商品、文章和列表卡片。返回标题、链接、来源、摘要、价格/评分等可提取字段、
卡片/控件 target 与页面语义。字段是否存在由页面决定，不保证每张卡字段齐全。
有效详情 URL 可直接导航；广告、账号、侧栏、店铺等不能自动当成用户需要的自然结果。
确定性脚本执行失败保留原始错误，不以“JSON 解析失败”为由重跑同一脚本。
真正响应解析失败的有限回退与模型重试不是同一层。

### tool browser_batch_interact

默认本地工具。必填 `steps` 和当前 `generation_id`（例如 `g3`）。
顶层 schema 和步骤字段详见 [runtime_tools.py][source-tools]。

| 参数 | 默认/限制 | 含义 |
|---|---|---|
| `steps` | 1..25 步 | 有序执行；每步必填 `op` |
| `generation_id` | 必填，`g[0-9]+` | 当前 PageState 代数 |
| `timeout_ms` | 2500，限制为 250..30000 | 默认动作单步超时 |
| `condition_timeout_ms` | 10000，限制在动作超时至 30000 | 默认条件等待超时 |
| `global_timeout_ms` | 按步骤估算，默认最多 120000，显式最多 180000 | Batch 整体上限 |
| `continue_on_error` | false | 兼容参数；不能据此假定任意失败都会继续，当前安全规则仅允许 optional 步骤继续 |
| `session_id` / `request_id` | 当前父任务上下文 | 显式提供时传给运行时 |

模型公开 schema 支持以下 21 种 op：

| 类别 | op |
|---|---|
| 动作 | `click`、`fill`、`type`、`autocomplete`、`select_visible_text`、`press`、`select_option`、`set_checked` |
| 条件等待 | `wait_for_selector`、`wait_for_text`、`wait_for_load_state`、`wait_for_url`、`wait_for_first_card_title`、`wait_for_sort_state`、`wait_for_result_count`、`wait_for_dom_text_change`、`wait_for_stable`、`wait_for_tab` |
| 结果 | `extract_text`、`extract_value`、`screenshot` |

底层 controller 还兼容 `sleep`，但模型 schema 不提供它；不推荐用固定 sleep 代替条件等待。
步骤常用参数：`target_id` / `ref`、`value`、`key`、`checked`、
`option_target_id` / `option_ref`、`option_text`、`field`、
`timeout_ms`、`optional`。定位策略互斥，动作必须绑定当前可执行目标。
URL/文本/排序等等待使用对应 `expected_*`、`url_contains`、`count` 等字段；
显式排序 attribute 必须给 expected_value，否则检查目标的实时选择状态。

- 单步骤存在等价 MCP primitive 时由 runtime 改写执行，不强迫模型重新调用。
- 多步骤先校验完整结构，再按执行顺序检查当时的目标可见性/唯一性，允许前一步使后续目标出现。
- 部分步骤成功后发生失败返回 `partial`，不是事务回滚；不得重放已成功的副作用步骤。
- 结果含 compact step 状态、提取值、条件观察、metrics 和 PageState。
  Batch `completed` 仅表示这批步骤完成，不等于整个用户 query 完成。

### tool browser_recall_offload

默认本地工具，由 [BrowserOffloadRecallTool][source-recall] 提供。

- 必填 `handle`：32 位十六进制标识，来自 `recall_handle` 或 `<persisted-output>`。
- `query`：可选、大小写不敏感的查找文本，最多 256 字符。
- `offset=0`：字符偏移；`limit=8000`：每次最多 16000 字符。
- 返回 `handle/found/content` 和分页信息；查无匹配不是读取到了空答案。
- 仅能读当前 browser Session 所属的浏览器 offload，不接受任意文件路径。
- 导航后回读出的 ref/selector 仅为历史证据，不能直接用于网页动作。

### 管理与兼容工具（非默认装配）

以下 Tool 类位于 [runtime_tools.py][source-tools]，但不在 `build_browser_runtime_tools()` 返回列表中。
宿主显式构造并加入 tools 后才成为模型工具；它们不是 capability 名称。

| 工具 | 参数 | 用途 |
|---|---|---|
| `browser_custom_action` | 必填 action；可选 params、session_id、request_id | 调用 controller 注册动作 |
| `browser_list_custom_actions` | 无 | 枚举动作与参数说明 |
| `browser_cancel_run` | 必填 session_id；可选 request_id | 设置取消标志并取消 service 记录的 inflight worker |
| `browser_clear_cancel` | 必填 session_id；可选 request_id | 清除标志；不自动重启被取消任务 |
| `browser_runtime_health` | 无 | 就绪、心跳、provider/model 诊断 |

controller 内置 action：`ping`、`echo`、`browser_task`、`run_browser_task`、
`browser_get_element_coordinates`、`browser_drag_and_drop`、`browser_batch_interact`、
`browser_set_input_files`、`list_upload_files`。action 是分发名称，不是九个默认模型 Tool。
嵌套 worker 中再次 browser_task 会被拒绝，避免递归派发。
`run_browser_task` / `BrowserService.run_task` 是兼容 worker 路径，和默认直接子智能体路径分开。

## Rails 与上下文处理

### Rail 分层

| Rail | 挂载位置 | 职责 |
|---|---|---|
| `BrowserRuntimeRail` | 浏览器 DeepAgent 自动注入 | 初始化、能力白名单、deadline、动作校验、证据与终态 |
| `ContextProcessorRail` | 浏览器 DeepAgent 自动注入或复用调用方同类 Rail | 调用 context engine，承载下面三个 processors |
| `SubagentRail` | 父 Agent，由调用方/宿主装配 | 创建子代理、注册 task_tool、传递任务上下文 |
| `BrowserTaskPromptRail` | JiuwenSwarm 父 Agent/成员侧，继承 SubagentRail | 仅在已加载 browser_agent 时补浏览器路由提示；保持浏览器同步 task_tool 路径 |
| 调用方 rails / 宿主权限和跟踪 rails | 取决于装配 | 不是 browser 工厂固定自带的安全/日志全家桶 |

`BrowserRunGuardrails` 是配置数据，不是一个 Rail。
`BrowserStateContextProcessor` / `BrowserWorkingContextProcessor` 是 processor，也不是单独 Rail。
通用事件路由、priority 与子代理约束见 [S_04][spec-rails]，不要绕过标准 DeepAgent 装配自行注册回调。

### class BrowserRuntimeRail

| Hook | 当前职责 |
|---|---|
| before_invoke | 必要时取得任务执行占用；启动 runtime/MCP；应用白名单；绑定观察回读；建立或恢复任务与期限 |
| before_model_call | 同步 runtime 状态、检查 deadline、注入图像能力说明；明确终态最多允许一次禁工具的自然语言总结 |
| after_model_call | 同一模型轮的工具组成 action group；阻止终态继续动作；对“只输出工具意图却没实际调用”的协议问题做有限纠正 |
| on_model_exception | 有限模型请求恢复；不能恢复时返回有证据的 partial 或 blocked，不伪造成功 |
| before_tool_call | 名称/参数/当前目标校验，处理无歧义别名、详情链接和单步 Batch，校验后才扣阶段/replan 预算 |
| after_tool_call | 归一真实执行成败；更新 PageState、证据和语义进展；保留必要原文并投影消息；汇总 action group |
| on_tool_exception | 进入同一 after_tool_call 结果处理，避免异常路径遗漏状态 |
| after_invoke | 校验完成请求，生成 authoritative_browser_result，保存可恢复状态；清理自身取得的占用与日志上下文 |

模型返回自然语言即可。旧 `<browser_progress>` 文本解析仍存在用于兼容，
但不再作为默认提示要求；即使旧输出声称 completed，也必须经过 runtime 的证据与完成条件校验。

### ContextProcessorRail 的三个 processors

工厂按以下顺序装配；调用方已有 ContextProcessorRail 时追加到其现有 processors，保留原有配置。

| Processor | 行为和默认预算 |
|---|---|
| `ToolResultWindowProcessor` | 覆盖 Probe 两类、snapshot、find、evaluate；最近 2 个结果保留，旧结果 trim 1000 字符，offload 阈值 1000 |
| `BrowserStateContextProcessor` | 首次和完成的浏览器 action group 后按需采集；只读观察合并紧凑状态，已知变更做必要刷新；当前页面投影默认 12000 字符 |
| `BrowserWorkingContextProcessor` | 注入 session 中 runtime 权威任务、证据和阻断项；工厂设置 runtime_projection_only=true，默认最多 8000 字符 |

页面状态/工作上下文是每次模型调用的临时消息，不向历史中重复追加完整页面。
结构先投影再 JSON 序列化，不能截断成不合法 JSON，也不能截短 URL/target 后让模型拿去执行。
页面原文属于不可信输入；共享上下文、白名单和这些预算都不是防 prompt injection 的独立安全沙箱。

### 结果保留与回读

两层保留要分清：

1. runtime 在有损投影前尝试保存观察原文，返回 `recall_handle`。
2. 通用 ToolResultWindowProcessor 对历史工具结果做窗口/offload，返回 persisted-output 标记。

runtime 观察文件位于 `<workspace>/context/<browser-session-id>_context/offload/BrowserObservation_<handle>.json`。
默认 TTL 24 小时，单个文件不超过 8 MiB，每个 session 目录最多 128 个/64 MiB；
写入时惰性清理，跨目录过期扫描每工作区最多每小时一次。
这是观察文件的保留策略，不应套用成所有历史日志或所有通用 offload 都在 24 小时删除。
结束任务不保证文件立即删除；写盘失败保留原文，不静默丢弃。
永久原始审计需要额外显式开启，回读工具不是任意文件访问入口。

## 页面状态与动作契约

- `page_id` 标识逻辑页面，`generation_id` 标识当前可执行目标代数。
- 导航和确认后的列表排序/筛选变化使旧目标失效；单纯重复只读观察不应每次递增 generation。
- Probe 公开 `target_id`，原生 snapshot/find 提供 AX ref。runtime 先解包 MCP 文本再登记原生 ref，
  不用不完整 Probe 结果覆盖原生观察。
- Batch 动作优先 target_id 或当前 AX ref；只读提取与明确条件等待可使用经过校验的 selector。
  schema 中存在 role/label/text 等兼容字段，不意味着可以绕过目标契约随意生成定位策略。
- 旧目标有可验证、唯一恢复路径时由 runtime 刷新；无法唯一映射时拒绝并要求重新观察。
- 卡片有真实详情链接时可改写为 navigate；fragment、javascript 链接及状态按钮仍保留点击语义。
- 语法或 schema 错误发生于执行前时返回 `executed=false/state_changed=false`；
  动作超时可能已经产生副作用，不能自动盲目重放。
- 一个模型轮的并发只读工具共用 action group，合并观察和预算；这不开放同一页面并发写动作。
- PageState 的页面 blocker 是启发式信息，不能直接覆盖 runtime 的任务终态。

## 任务结果与证据

### 权威状态

| 状态 | 含义 |
|---|---|
| `in_progress` | 可以继续执行，受目标、阶段和剩余预算约束 |
| `completed` | runtime 接受已有证据与用户目标的完成关系 |
| `partial` | 保留部分成果，但存在未完成要求、期限或可纠正问题 |
| `blocked` | 当前执行受阻，不能用模型一句“完成”覆盖 |

原始用户目标通过 task_tool 的 run context 传递。字段推断是提取提示，不应增加用户未提出的要求。
普通问答可以用有来源的已读原文和最终回答完成，未映射字段列为 `unverified_fields`；
对比对象、评分类型、日期/报价口径、数量和明确未知字段不能互相替代。
证据绑定 query、entity URL、variant、field 和来源；搜索卡标题不证明进入过详情，
店铺评分不证明商品评分，旧页面不证明新 query 已完成。
完成时仍检查事实矛盾；例如要求进入详情却仍停留搜索页，可将错误 completed 降为 partial。

### 返回契约

DeepAgent 保留结构化 `authoritative_browser_result`，
并在 `output` 中输出 `{"browser_result": ...}` JSON。
`completed` 对应 `result_type="answer"`，partial/blocked 对应 `result_type="error"`。
不能只检查 output 非空或 result_type 就丢弃部分成果。

主要字段：

| 字段 | 用途 |
|---|---|
| status、task_id、current_phase、terminal_reason | 任务终态与原因 |
| summary、observations、evidence、current_page | 已取得的自然语言结果、观察和证据 |
| requested_slots、missing_slots、unavailable_slots | 请求、尚缺和明确不可用的证据槽 |
| missing_fields、unverified_fields、field_coverage | 字段完成度；未结构化不等于事实错误 |
| requested_result_count、observed_result_count | 数量目标和观测结果 |
| blockers、retryable、recommended_recovery | 阻断与允许的恢复方式 |
| resume_count、deadline | 恢复计数、剩余期限；不能无限续跑 |

task_tool 再向父 Agent 返回 `browser_result`、`resume_task_id`、`retryable`、
`resume_context`、`query_id`，并在模型可见文本保留 browser_orchestration。
如果结构化权威结果在传输中丢失，按 transport failure 处理，不把残缺流式文本当成功。
自然语言 summary 不得覆盖 runtime 状态；partial 也应保留有用结果。
`retryable=true` 是许可，不是要求模型一定重试。

## 生命周期与资源所有权

### class BrowserAgentRuntime

模块：`openjiuwen.harness.tools.browser_move.playwright_runtime.runtime`。
构造参数为 provider、api_key、api_base、model_name、mcp_cfg、guardrails，
以及可选 instance、allowed_tool_names。通常由工厂管理，而不是由业务代码逐个构造内部工具。

| 方法 | 管理职责 |
|---|---|
| `acquire_task_resources()` / `release_task_resources()` | 获取/释放整个任务的浏览器执行占用和资源绑定 |
| `ensure_runtime_ready()` | 启动/连接浏览器和 MCP，绑定内部代码 transport 与 controller，不创建嵌套 LLM worker |
| `ensure_started()` | 兼容路径进一步创建 worker 和 controller 工具绑定；不是默认直接路径的必要第二层 Agent |
| `export_page_state()` / `capture_browser_state()` | 当前页目标投影 / 实际页面采集 |
| `probe_interactives()` / `probe_cards()` / `batch_interact()` | 默认辅助工具的执行实现 |
| `run_custom_action()` / `list_actions()` | controller 动作分发与发现 |
| `run_browser_task()` | 兼容自然语言 worker 调用 |
| `cancel_run()` / `clear_cancel()` | service 取消标志和兼容 worker 的取消控制 |
| `runtime_health()` | runtime/heartbeat 诊断，不是模型自动注册工具 |
| `reset()` / `shutdown()` | 显式重置或关闭本身份的资源，见下表 |

### 一次任务的完整顺序

1. 父 task_tool 校验请求并绑定父 query；检查同 query 是否正在执行、已完成或还有恢复配额。
2. 取得/创建子 Agent，确定 child Session 身份。BrowserService 对象与任务/装配相关，不是全局共享模型记忆。
3. prepare 钩子通过 `BrowserServiceRegistry.task_turn` 获取执行占用并 acquire_task_binding；随后创建/准备 child Session。
4. 按需启动 managed Chrome 或连接 remote/extension；注册 MCP；启动单一 owner 的 heartbeat。
5. 模型和工具循环更新 PageState、证据及任务预算。
6. 最终结构化结果经过 ReAct stream、DeepAgent 和 task_tool 完整传递。
7. finally 清理内层执行者、observer、任务引用与 MCP 绑定，最后释放 task_turn。
8. 保留的 Chrome/Profile/Cookie 可供下一任务使用，但新任务上下文和旧目标必须正确隔离。

### 三种清理的区别

| 操作 | 任务和 MCP | Chrome/Profile |
|---|---|---|
| `release_task_resources()` | 引用归零后停止本 service heartbeat，移除不再使用的 MCP，清 observer/inflight/任务状态；释放执行占用 | 保留 managed Chrome 和磁盘 Profile |
| `reset()` | 协调同一资源身份的服务解绑；下一次按需启动 | 停止该身份记录的 managed 驱动，不删除 Profile/Cookie |
| `shutdown()` | reset 后释放残留任务绑定并丢弃空闲 registry 项 | 清本 runtime 管理的资源；不应等同于终止所有外部 Chrome/Electron |

SDK 的 shutdown 不全局调用 Runner.stop，避免关闭其他 Agent 的共享 Runner。
外部浏览器进程和 Electron 面板生命周期归宿主管理，remote detach 不承诺关闭整个外部进程。
reset/shutdown 会影响同一资源身份的其他绑定，宿主应先停止相关任务再执行显式重置，
不能把它们当成可以随时并发调用而不影响正在运行任务的无副作用操作。

### 浏览器共享与隔离

`BrowserServiceIdentity` 记录 browser_key、profile_name、driver/display mode、启动参数、
browser_binary、user_data_dir、CDP endpoint、server_id，协调 MCP、驱动句柄与 heartbeat 所有权。

任务级互斥单独按 `browser_key`（为空时按 server_id）排队，覆盖准备至 cleanup，
而不是每次工具调用各锁一下。它支持同进程跨事件循环线程等待，取消等待不会留下一条以后偷偷拿到锁的后台线程。

- 同 key 意味着主动共享浏览器，任务串行；不同 key 可以并行。
- 不同 key 但手动指向相同 CDP/tab，仍可能互相干扰，SDK 不自动识别所有物理页面别名。
- 这是进程内协调，不是分布式锁；多进程指向同一浏览器需宿主统一身份/路由。
- 页面隔离、Cookie 共享和模型 Session 隔离是三个独立选择。
- 不要让多个运行中的 Chrome 进程同时使用同一 user-data-dir 来强行共享登录态。

## 超时与恢复

### 默认直接子智能体路径

| 限制 | 当前值/行为 |
|---|---|
| 浏览器模型迭代上限 | create_browser_agent 默认 100，可由宿主配置覆盖 |
| task_tool 总调用保护 | 默认 720 秒；更短的宿主 execution_deadline_at 优先 |
| 同 query 总预算 | 简单任务 240 秒、复杂任务 600 秒；初次调用和恢复共享 |
| 同 query focused resume | 最多 1 次；完成、过期、非 retryable 或配额用完时返回已有结果/拒绝再次执行 |
| 模型异常恢复 | runtime 最多 1 次有限恢复，仍受剩余期限约束 |
| 模型“意图未执行”协议纠正 | 最多 1 次，不能把描述工具意图当成已执行 |
| 阶段预算 | navigation 12、form 24、filtering 20、extraction 20 |
| replan | 语义无进展和策略重复受门控；拒绝预算 3，受限只读恢复 1 |
| Batch/单个 transport | 还有各自超时，不能理解成可延长 query 总期限 |

简单/复杂是现有关键词规则，不是额外 LLM 分类器。
阶段预算是执行准入约束，不应简单等同于用户看到的 MCP 调用次数；
schema 校验失败、内部确定性恢复和并发只读 action group 有各自记账规则。
query 时钟包含已消耗的等待时间，但启动/排队和清理还受外层调用超时管理，
不能将表中数字理解成浏览器进程会在该毫秒被强制终止。超时也不承诺回滚已完成的网页副作用。

宿主通过 `run.context.extra.execution_deadline_at`（epoch 秒）传入更短期限，
SubagentRail 写入父 session，task_tool 收紧 browser_query_deadline_at 并限制实际 await；
JiuwenSwarm 心跳执行路径也传递此期限。不要混用 epoch 与 monotonic 时间。

### 恢复不是重新开始

父 task_tool 优先用当前 usage invocation id 识别 query；没有时使用父 session 与任务文本的稳定摘要。
恢复必须引用本父 session 的 `resume_task_id`。
保持原目标、证据、task/query 身份与总期限，只生成针对缺失项的修复指令；
不会因为换一段 task_description 就重置同一 query 的恢复预算。
新父请求/新 query 可产生新预算，故这不是跨所有会话的全局“最多重试一次”。

### 取消与人工接手

- 默认直接路径由父 task/stream 的取消控制执行者。ReAct 消费者取消或 aclose 后取消并等待 producer；
  TaskTool 与 callback/session 包装器关闭内层生成器，清理 observer 后再释放浏览器占用。
- 超时尽量返回 child Session 中已取得的部分证据；取消保存结果后继续传播 CancelledError，
  不能把取消吞成成功并继续点击。
- `browser_cancel_run` 对 service 记录的兼容 worker 有效，不代替宿主对直接 Agent task 的取消。
- `browser_clear_cancel` 只是清标志，`browser_resume` 是 MCP 调试操作；
  两者都不等同于 task_tool 的 focused resume。
- 用户移动鼠标或点击页面不等于系统已自动中断 Agent。人工接手需要宿主显式停止/取消；
  页面状态刷新可检测变化，但不是自动人机控制权仲裁器。

## 实例配置与浏览器模式

### class BrowserInstanceConfig

| 字段 | 默认 | 说明 |
|---|---|---|
| key | 空 | 隔离身份，规范化为字母/数字/下划线/连字符；避免不同原值规范化后碰撞 |
| driver_mode | 空 | managed / remote / extension；空时读取 BROWSER_DRIVER |
| managed_port | 0 | 显式正值优先；有 key 时自动空闲端口，否则 BROWSER_MANAGED_PORT 或 9333 |
| user_data_dir | 空 | 显式目录优先，否则按 profile 派生 |
| profile_name | 空 | instance.profile_name -> 规范化 key -> BROWSER_PROFILE_NAME -> jiuwenclaw |
| cdp_url | 空 | 显式 remote endpoint，优先于共享 CDP 环境配置 |
| browser_binary | 空 | 显式浏览器可执行文件覆盖 |

纯 SDK 未配置 driver 时默认 remote；JiuwenSwarm 正常外部浏览器接入会设置 managed。
不能用 SDK 默认值推断宿主部署实际模式。

### class RuntimeSettings

字段：provider、api_key、api_base、model_name、mcp_cfg、guardrails、instance。
不要将密钥或带认证的完整代理 URL 写入日志/示例。

| 模式 | 谁启动浏览器 | 有头/无头 | 登录状态 |
|---|---|---|---|
| managed | SDK ManagedBrowserDriver | 通过 BROWSER_MANAGED_ARGS 等启动参数决定 | 持久化 user-data-dir |
| remote | 外部 CDP 宿主 | SDK 不能用 headless 参数改变已运行浏览器 | 由外部浏览器保存 |
| extension | 扩展和现有浏览器 | 由已运行浏览器决定 | 使用扩展所连接的浏览器状态 |

配置组合须一致。尤其 extension 也依赖 PLAYWRIGHT_MCP_EXTENSION/--extension，
不能仅改一个 instance.driver_mode 就假定继承的 MCP 参数全部同步改变。
CDP 模式仅适用于 Chromium；配置 CDP endpoint 时不能同时配置 Playwright device 模拟。

默认 MCP command 为 npx，args 为 `-y @playwright/mcp@0.0.78`；
支持通过 command/args/env_json 或宿主内置 Node/MCP 包替换，不要求打包环境一定联网下载。

默认 profile 注册表为 `<mcp_cwd>/.browser/profiles.json`，可由 BROWSER_PROFILE_STORE_PATH 指定。
默认 managed 数据目录通常为 `<mcp_cwd>/.browser-profiles/<profile_name>`；
显式目录和 BROWSER_MANAGED_KILL_EXISTING 的兼容行为可能改变此选择。
profile JSON 是连接注册信息，不是 Cookie 数据库。
MCP cwd 优先读取 PLAYWRIGHT_RUNTIME_MCP_CWD、BROWSER_RUNTIME_MCP_CWD、
PLAYWRIGHT_RUNTIME_WORKDIR、BROWSER_RUNTIME_WORKDIR，否则使用当前工作目录。

## JiuwenSwarm 接入

本节说明宿主行为，不是纯 SDK 工厂保证。源码相对 JiuwenSwarm 仓库根目录：

| jiuwenswarm/agents/harness/common/prompt/browser_task_prompt.py | 浏览器优先、保留用户原始目标、避免无意义搜索预检/反复验证 |
| jiuwenswarm/server/runtime/agent_adapter/interface_deep.py | 构造 browser preset、同步运行配置和安全设置、单会话 Electron 绑定 |
| jiuwenswarm/agents/swarm/providers/code_subagents.py | session/成员派生 browser_key |
| jiuwenswarm/agents/swarm/browser_runtime.py | Electron 下 Swarm 显式 Chrome 兜底 |
| jiuwenswarm/agents/harness/common/electron_sideview.py | 每会话/成员 MCP 身份、target resolver 与显式 discovery |

| jiuwenswarm/channels/desktop/electron/target_mcp_wrapper.cjs | MCP 页面绑定/租约与转发 |

- 浏览器意图走同步 task_tool，不走通用异步 subagent_spawn，也不先用 paid_search/fetch 做预检。
- 派发只带原目标和必要约束；普通问答可读站点顶部 AI/知识/天气答案并注明来源；
  用户明确要求自然结果或进入详情时仍须执行。
- Electron 单 Agent 按 session 绑定独立 MCP server_id/面板；Swarm 按 session + member 绑定。
  多个面板使用宿主共享持久化 partition，因此操作页面分开但 Cookie/登录态可共享。
- Electron 下只有 Swarm 在明确配置 Chrome 路径时走外部 managed 兜底，读取原有有头/无头设置；
  单 Agent 仍走内置面板。
- 外部 managed 兜底使用独立成员 Profile，不保证共享 Electron 的登录态。
- 非 Electron 单 Agent 路径没有自动传入唯一 browser_key 时，仍可能共享同一外部浏览器；
  进程内 task_turn 会排队，但“排队使用同一浏览器”不是“每会话一个独立页面”。
- SDK 的 browser_tabs 等能力进入 Electron 包装器后有宿主语义约束，不能把能力目录当作
  完整桌面 Chrome tab 行为承诺，也不能把内置面板当作安全沙箱。
- UI 手动配置、实际打开的面板和 EXE 内绑定的 SDK 版本可能不同；排障需核对当前运行配置。

## 可观测性与排障

### 日志与状态

纯 SDK 专用 logger 是 `openjiuwen.browser_agent`，默认文件 `./logs/browser_agent.log`，
相对于进程工作目录；OPENJIUWEN_BROWSER_AGENT_LOG_FILE 可覆盖，
0/false/no/off 等值可禁用。宿主可能重定向目录，不能一概认定在安装目录或 .logs。
BROWSER_SUBAGENT_STATUS_LOG 默认开启状态记录；OPENJIUWEN_BROWSER_AGENT_LOG_MIRROR_COMMON
控制是否镜像通用日志。OPENJIUWEN_BROWSER_AGENT_AUDIT_RAW 控制原始审计，需评估页面和登录信息泄露风险。

排障同时保留父任务/子任务 ID、query_id、MCP server_id、browser_key、当前 URL/generation、
结构化 browser_result 和具体工具错误。只看 UI 最后一段文字不能还原生命周期。

### 常见症状

| 症状 | 首先检查 |
|---|---|
| 页面能打开但 Probe/Batch 失败 | MCP 底层代码执行 transport 是否被包装器删除；真实脚本错误，而非盲目重试 |
| 截图工具未注册 | 是否选择 vision；agent 图像输入能力；宿主权限和 MCP tools/list |
| 取消/健康检查工具找不到 | 它们不是默认模型工具，检查是否显式装配或改用宿主 API |
| 操作旧 ref 报错 | generation 是否变化；是否误用了 offload 中的旧 target |
| partial 仍有答案却重复跑 | browser_result.observations/summary/unverified_fields 与真正未回答的要求 |
| 不同会话互相跳页 | browser_key、server_id、CDP target 是否真正不同，不只看 session_id |
| 任务结束 Chrome 未关闭 | release 保留 Profile/进程是设计；需要的是 reset/shutdown 还是宿主关闭 |
| 恢复直接被拒绝 | deadline、resume_count、retryable、父 session 是否匹配 |
| 看见旧协议描述 | 核对实际加载 SDK 路径；本文本地改动不自动进入旧 EXE/锁定版 |
