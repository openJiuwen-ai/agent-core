# HTTP 出口的 CP5 正文观察

宿主通过 `bind_operation_observer()` 绑定观察器后，`sync_client` 和 `async_client`
在实际 HTTP 请求之前产生 `network_send`。两者使用同一套正文预览逻辑，事件参数为
`{"url": "...", "data": "..."}`；观察器拒绝时，请求不会发出。未绑定观察器或正在
执行观察器自身的上报时，不额外预读正文。

## 正文表示

所有预览合计最多 **8192 个 UTF-8 字节**，不改变实际请求的长度和内容。

| 输入 | `data` 预览 |
| --- | --- |
| `json=` | JSON 文本前缀；requests 同时提供非空 `data` 时，以实际发送的 data 为准 |
| `data=str/bytes/bytearray/memoryview` | 可解码文本前缀；二进制或不可解码内容使用 `<binary/unavailable>` |
| 字典、键值对列表/元组 | URL 编码的表单预览，保留重复字段和列表值 |
| 同步 `files=` | 表单字段、文件名、可取得的总大小，以及文件内容前缀 |
| 异步 `aiohttp.FormData` | URL 编码或 multipart 字段/文件预览；不会调用 FormData 的消费式序列化接口 |
| 可回退的同步 file-like | 从当前读取位置开始预览，结束后恢复原位置 |
| 生成器、异步迭代器、不可回退流、自定义/预构建 payload | `<binary/unavailable>`，不消费数据以猜测正文 |
| 空正文 | 空字符串 |

文件预览示例：

```text
[file {"field": "upload", "filename": "note.txt", "size": 12000}]
文件内容的有限前缀……
```

文件大小表示可取得的总字节数；未知时为 `null`。multipart 预览是字段和文件摘要，
不是带随机 boundary 的原始 HTTP 字节流。前面字段用尽 8192 字节预算时，后续部分
不会进入预览；文件名和大小不能证明文件正文已经完整检测。

`aiohttp.FormData` 没有公开的非消费式字段枚举接口，当前适配只读其 `_fields`；
布局不受支持或 multipart 已生成时使用不可用标记，不清空字段或重新序列化上传体。

## 对上传和授权的影响

- 观察逻辑不替换原始 kwargs、文件对象或请求头。
- 预读先检查回退能力，读取后在 `finally` 中恢复文件位置。读取失败可使用不可用标记；
  如果位置恢复失败，抛出错误并停止本次 HTTP 发送，避免发送缺失前缀的正文。
- 异步入口在线程中完成预览，取消时等位置恢复后再结束；不关闭调用方提供的文件。
- `<binary/unavailable>` 表示正文未能采集，不是“没有敏感内容”或授权允许。
  宿主负责后续内容匹配及授权处理；现有域名规则、CP5 等待开关和云端裁决规则不变。
- 预览不包括 URL 查询参数、请求头或协议加密层的内容；完整性范围以本表为准。

回归包含模拟观察器，以及本机 HTTP 服务对照：开启和关闭观察时，表单、JSON、
字符串、字节、文件流和 multipart 的服务器接收内容保持一致。
