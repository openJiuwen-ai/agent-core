# 知识检索

知识检索（Retrieval）是openJiuwen框架的核心组件，主要负责知识库的管理和文档检索。它提供了对文档解析、分块、索引构建、向量检索等标准化管理能力，帮助开发者在构建Agent时更高效地处理知识内容。

在智能对话场景中，用户需要从大量文档中快速准确地检索相关信息。知识检索通过向量化、索引化等方式管理这些信息，能够帮助Agent更好地理解上下文，提供准确的答案。

知识检索的开发流程分为以下两步：

1. 创建知识库实例：以```SimpleKnowledgeBase```为例创建知识库实例，支持自定义配置包括向量存储、嵌入模型、文档解析器、文本分块器等，实现知识库功能的初始化。
2. 使用知识库实例：支持添加文档、构建索引、检索文档等主要操作，帮助智能体更好地利用知识内容。

> **参考实现**：基于 `SimpleKnowledgeBase` 的示例项目。该项目实现了一个持续更新的 PEP（Python Enhancement Proposals）知识库，用于为代码的审视与修复提供风格与规范层面的专业建议。详见 [TomatoReviewer](https://gitcode.com/SushiNinja/TomatoReviewer)。

# 创建知识库实例

通过```SimpleKnowledgeBase```创建知识库实例，需要传入相应的配置参数。配置包括知识库ID、索引类型（vector/bm25/hybrid）等。另外知识库中的数据存放涉及向量存储、嵌入模型、索引管理器等，也需要初始化的时候进行配置。在`openjiuwen.core.retrieval`下提供了默认实现，也可以自定义实现。

下面以使用默认的```MilvusVectorStore```、```OpenAIEmbedding```和```MilvusIndexer```为例，说明如何创建知识库实例。

```python
import asyncio

from openjiuwen.core.retrieval.common.config import (
    EmbeddingConfig,
    KnowledgeBaseConfig,
    RetrievalConfig,
    StoreType,
    VectorStoreConfig,
)
from openjiuwen.core.retrieval.embedding.openai_embedding import OpenAIEmbedding
from openjiuwen.core.retrieval.indexing.indexer.milvus_indexer import MilvusIndexer
from openjiuwen.core.retrieval.indexing.processor.chunker.chunking import TextChunker
from openjiuwen.core.retrieval.indexing.processor.parser.auto_file_parser import AutoFileParser
from openjiuwen.core.retrieval.simple_knowledge_base import SimpleKnowledgeBase
from openjiuwen.core.retrieval.vector_store.milvus_store import MilvusVectorStore


async def create_kb() -> None:
    """创建知识库"""
    # 定义知识库配置
    kb_config = KnowledgeBaseConfig(
        kb_id="test_kb_001",
        index_type="hybrid",  # 支持 vector、bm25、hybrid
        use_graph=False,
        chunk_size=512,
        chunk_overlap=50,
    )

    # 创建向量存储
    # milvus_uri表示Milvus服务的主机地址（默认为http://localhost:19530）, milvus_token为用于身份认证的key（默认为空）
    vector_store_config = VectorStoreConfig(
        store_provider=StoreType.Milvus,
        collection_name=f"kb_{kb_config.kb_id}_chunks",
        distance_metric="cosine",
    )
    milvus_uri = "http://localhost:19530"
    milvus_token = ""
    vector_store = MilvusVectorStore(
        config=vector_store_config,
        milvus_uri=milvus_uri,
        milvus_token=milvus_token,
    )

    # 创建嵌入模型
    # model_name表示使用的embedding模型名, base_url表示请求embedding API的地址, api_key表示密钥, max_retries表示最大重试次数, timeout表示请求超时时间
    embedding_config = EmbeddingConfig(
        model_name="xxxxx",
        api_key="sk-xxxxx",
        base_url="http://xxxxx",
    )

    # You can specify embedding dimension or leave it at default
    embed_model = OpenAIEmbedding(config=embedding_config, max_retries=3, timeout=60, dimension=128)

    # 创建索引管理器（与向量存储共用 VectorStoreConfig）
    indexer = MilvusIndexer(
        config=vector_store_config,
        milvus_uri=milvus_uri,
        milvus_token=milvus_token,
    )

    # 创建文档解析器（自动识别文件格式）
    parser = AutoFileParser()

    # 创建文本分块器
    chunker = TextChunker(
        chunk_size=kb_config.chunk_size,
        chunk_overlap=kb_config.chunk_overlap,
        chunk_unit="token",  # 支持 char 或 token
    )

    # 创建知识库实例
    knowledge_base = SimpleKnowledgeBase(
        config=kb_config,
        vector_store=vector_store,
        embed_model=embed_model,
        parser=parser,
        chunker=chunker,
        index_manager=indexer,
    )

    return knowledge_base
```

## 文档解析器（Parser）

知识库支持通过不同的解析器处理文档来源，常用解析器如下：

| 解析器 | 说明 | 适用场景 |
|--------|------|----------|
| **AutoFileParser** | 按文件扩展名自动选择解析器，支持多种本地文件格式 | 仅处理本地文件时使用 |
| **AutoLinkParser** | 按 URL 自动选择解析器，支持微信公众号文章（mp.weixin.qq.com）与普通网页（http(s)） | 仅处理链接时使用 |
| **AutoParser** | 统一入口：URL 走链接解析，本地路径走文件解析，可同时支持文件与链接 | 需要同时支持本地文件和网页/公众号链接时使用 |

**AutoFileParser 当前支持的文件格式**：PDF（.pdf）、文本/Markdown（.txt / .md / .markdown）、Word（.docx）、Excel/CSV/TSV（.xlsx / .csv / .tsv）、JSON（.json）、HTML（.html / .htm）、图片（.png / .jpg / .jpeg / .webp / .gif / .jfif）。可通过 `@register_parser` 装饰器扩展新格式。

若需同时导入本地文件和网页链接，可将 `parser` 设为 `AutoParser()`，并从 `openjiuwen.core.retrieval` 导入。使用 `AutoParser` 时，可直接在 `parse_files` 中传入混合的本地文件路径与 URL 列表，无需区分接口：

```python
from openjiuwen.core.retrieval import AutoParser

parser = AutoParser()
# 后续在 parse_files 中可传入混合列表，例如：
# documents = await knowledge_base.parse_files(["./doc1.pdf", "https://mp.weixin.qq.com/...", "./doc2.txt"])
```

# 使用知识库实例

知识库支持添加文档、检索文档、删除文档、更新文档等主要操作。

## 添加文档

通过```parse_files```和```add_documents```方法可以添加文档到知识库，知识库会自动进行文档解析、分块、索引构建等处理。

```python
async def add_documents(knowledge_base: SimpleKnowledgeBase) -> None:
    """添加文档"""
    # 准备文档文件路径
    file_paths = [
        "./documents/doc1.pdf",
        "./documents/doc2.txt",
        "./documents/doc3.md",
    ]

    # 解析文件为Document对象列表
    documents = await knowledge_base.parse_files(file_paths)

    # 添加doc id
    for doc_idx, doc in enumerate(documents, 1):
        doc.id_ = f"doc_id_{doc_idx}"

    # 添加文档到知识库（自动分块和构建索引）
    doc_ids = await knowledge_base.add_documents(documents)
    print(f"成功添加 {len(doc_ids)} 个文档，文档ID: {doc_ids}")
```

## 检索文档

通过```retrieve```方法可以检索相关文档，支持向量检索、稀疏检索和混合检索。

```python
async def retrieval(knowledge_base: SimpleKnowledgeBase) -> None:
    # 配置检索参数
    retrieval_config = RetrievalConfig(
        top_k=3,  # 返回前3个结果
        filters=None,  # 元数据过滤条件（可选）
    )

    # 执行检索
    query = "什么是人工智能？"
    results = await knowledge_base.retrieve(query, config=retrieval_config)

    # 打印检索结果
    for i, result in enumerate(results, 1):
        print(f"\n结果 {i}:")
        print(f"  文本: {result.text[:100]}...")
        print(f"  相似度: {result.score:.4f}")
        print(f"  文档ID: {result.doc_id}")
        print(f"  块ID: {result.chunk_id}")
```

## 重排序器（Reranker）

在向量检索之后，可以使用**重排序器（Reranker）**对召回结果进行二次精排。Reranker 基于交叉编码（cross-encoder）模型，将 query 与每个候选文档共同送入模型打分，从而获得比单纯向量相似度更精准的相关性排序。

> 说明：Reranker 是一个独立的工具类，**不**绑定到知识库的 `retrieve` 流程中。你可以在拿到召回结果后，自行调用 `rerank` / `rerank_sync` 对候选列表重排，再取 Top-K。

### 内置实现

openJiuwen 在 `openjiuwen.core.retrieval.reranker` 下提供以下实现，均继承自抽象基类 `Reranker`（定义于 `openjiuwen.core.foundation.store.base_reranker`）：

| 实现类 | 说明 | 适用场景 |
|--------|------|----------|
| **StandardReranker** | 标准 rerank 客户端，对接 vLLM 风格的 `/rerank` 接口 | 自建/开源 rerank 服务（如 vLLM 部署的 bge-reranker 等） |
| **ChatReranker** | 基于 chat 接口的 reranker | 通过对话接口完成打分的模型 |
| **DashscopeReranker** | 阿里云灵积（DashScope）`text-rerank` 接口客户端，支持原生异步调用 | 使用阿里云 DashScope 的 `gte-rerank` 系列模型 |

这三个实现均通过 `openjiuwen.core.retrieval` 惰性导入，可直接 `from openjiuwen.core.retrieval import DashscopeReranker` 使用，无需注册。

### RerankerConfig 配置

`RerankerConfig`（定义于 `openjiuwen.core.foundation.store.base_reranker`）用于配置 reranker 的鉴权与请求参数：

| 参数名 | 类型 | 必填 | 默认值 | 说明 |
|--------|------|------|--------|------|
| `api_key` | str | 否 | `""` | 调用 rerank 服务的 API 密钥 |
| `api_base` | str | 是 | - | rerank 服务的基础 URL |
| `model_name` | str | 否 | `""` | 模型名称，支持别名 `model` |
| `timeout` | float | 否 | `10` | 请求超时时间（秒，需 > 0） |
| `temperature` | float | 否 | `0.95` | 采样温度 |
| `top_p` | float | 否 | `0.1` | Top-p 采样参数 |
| `yes_no_ids` | tuple[int, int] | 否 | `None` | "yes"/"no" 的 token id（用于 yes/no 打分模式） |
| `extra_body` | dict | 否 | `{}` | 透传给服务的额外参数 |

### 使用示例：DashscopeReranker

下面以 `DashscopeReranker` 为例，演示如何对一组候选文档重排序。`DashscopeReranker` 继承自 `StandardReranker`，因此构造参数与 `StandardReranker` 一致：

```python
import asyncio

from openjiuwen.core.retrieval import DashscopeReranker
from openjiuwen.core.foundation.store.base_reranker import RerankerConfig


async def rerank_demo() -> None:
    # 1. 配置 reranker（以阿里云 DashScope 的 gte-rerank 为例）
    config = RerankerConfig(
        api_key="sk-xxxxx",                          # DashScope API Key
        api_base="https://dashscope.aliyuncs.com",   # DashScope 服务地址
        model="gte-rerank",                          # 模型名（别名，等价于 model_name）
    )

    # max_retries: 失败重试次数; retry_wait: 重试间隔; verify: SSL 校验
    reranker = DashscopeReranker(
        config=config,
        max_retries=3,
        retry_wait=0.1,
    )

    # 2. 准备候选文档（可以是 str，也可以是 Document 对象）
    query = "什么是人工智能？"
    candidates = [
        "人工智能是研究、开发用于模拟、延伸和扩展人的智能的理论与方法的一门学科。",
        "杭州是浙江省的省会城市。",
        "深度学习是机器学习的一个分支，使用多层神经网络进行特征学习。",
    ]

    # 3. 异步重排序，返回 {文档文本/ID: 相关性分数} 映射
    scores: dict[str, float] = await reranker.rerank(
        query=query,
        doc=candidates,
        instruct=True,  # True 使用默认指令；也可传入 str 自定义指令
    )

    # 4. 按分数降序取 Top-K
    ranked = sorted(scores.items(), key=lambda kv: kv[1], reverse=True)
    for i, (text, score) in enumerate(ranked, 1):
        print(f"{i}. score={score:.4f}  {text[:40]}...")

    # 同步接口用法（在非异步上下文中）：
    # scores = reranker.rerank_sync(query=query, doc=candidates, instruct=True)


if __name__ == "__main__":
    asyncio.run(rerank_demo())
```

输出示例：

```
1. score=0.9821  人工智能是研究、开发用于模拟、延伸和扩展人的智...
2. score=0.6430  深度学习是机器学习的一个分支，使用多层神经网络...
3. score=0.0512  杭州是浙江省的省会城市。
```

> **关于 `instruct` 参数**：`instruct` 控制是否向 reranker 注入检索指令。`True` 使用默认指令（`StandardReranker.default_instruct`）；传入字符串则使用自定义指令；`False` 则不注入指令。不同模型对指令的支持不同，请按所用模型文档调整。
>
> **`StandardReranker` 与 `DashscopeReranker` 的区别**：两者构造参数与方法签名相同，区别仅在请求组装与端点。`StandardReranker` 走 `/rerank` 端点（vLLM 风格）；`DashscopeReranker` 走 DashScope 的 `/services/rerank/text-rerank/text-rerank` 端点，并支持多模态输入。

## 多轮检索场景下的 Query 重写器

在不使用智能检索时，仍可通过独立的 **QueryRewriter** 在多轮对话中提升检索效果。它基于上下文（通过 context engine）对用户 query 做指代消解、去口语化和歧义修正。每一轮先调用 `await rewriter.rewrite(user_message)` 得到 `standalone_query`，再将该值传入 `knowledge_base.retrieve(standalone_query, ...)`。重写器不会自行更新上下文；调用方应在每轮后将用户与助手消息追加到上下文中。

- API：[QueryRewriter](../API文档/openjiuwen.core/retrieval/query_rewriter/query_rewriter.md)
- 示例：更多使用示例请参考 [openJiuwen/agent-core](https://gitcode.com/openJiuwen/agent-core/) 仓库中 `examples/retrieval/` 目录下的示例代码，包括：`showcase_query_rewriter.py`（多轮检索场景下的 Query 重写器用法）。

## 多知识库联合检索

`openjiuwen.core.retrieval.simple_knowledge_base` 还提供了多知识库联合检索的辅助函数，适合在一个请求中同时查询多个 `KnowledgeBase`：

- `retrieve_multi_kb(kbs: list[KnowledgeBase], query: str, config: RetrievalConfig | None = None, top_k: int | None = None) -> list[str]`
- `retrieve_multi_kb_with_source(kbs: list[KnowledgeBase], query: str, config: RetrievalConfig | None = None, top_k: int | None = None) -> list[MultiKBRetrievalResult]`

示例：

```python
from openjiuwen.core.retrieval.simple_knowledge_base import (
    retrieve_multi_kb,
    retrieve_multi_kb_with_source,
)


async def search_across_kbs(kbs: list[SimpleKnowledgeBase]) -> None:
    query = "什么是向量检索？"

    # 仅返回去重后的文本结果
    texts = await retrieve_multi_kb(kbs, query, config=RetrievalConfig(top_k=5))
    for i, t in enumerate(texts, 1):
        print(f"{i}. {t}")

    # 返回包含来源信息的结果（每项为 MultiKBRetrievalResult 对象）
    results = await retrieve_multi_kb_with_source(kbs, query, config=RetrievalConfig(top_k=5))
    for item in results:
        print(f"text={item.text}, score={item.score}, kb_ids={list(item.kb_ids)}")
```

## 智能检索（Agentic Retrieval）

`SimpleKnowledgeBase` 和 `GraphKnowledgeBase` 均支持**智能检索（Agentic Retrieval）**——一种基于LLM的迭代检索策略，能够自动重写查询并在多轮检索中融合结果，以获得更高的召回率和精度。

要启用智能检索，请在 `RetrievalConfig` 中设置 `agentic=True`，并在创建知识库时提供 `llm_client`：

### 使用 SimpleKnowledgeBase 进行智能检索
```python
from openjiuwen.core.foundation.llm.model_clients.openai_model_client import OpenAIModelClient

# 创建用于智能检索的LLM客户端
llm_client = OpenAIModelClient(
    api_key="sk-xxxxx",
    base_url="http://xxxxx",
    model="<model_name>",
)

# 创建知识库时传入llm_client
knowledge_base = SimpleKnowledgeBase(
    config=kb_config,
    vector_store=vector_store,
    embed_model=embed_model,
    llm_client=llm_client,  # 智能检索必需
)

# 通过RetrievalConfig启用智能检索
retrieval_config = RetrievalConfig(
    top_k=5,
    agentic=True,  # 启用智能检索
)

results = await knowledge_base.retrieve("复杂的多跳问题", config=retrieval_config)
```

### 使用 GraphKnowledgeBase 进行智能检索

```python
from openjiuwen.core.foundation.llm.model_clients.openai_model_client import OpenAIModelClient

# 创建用于智能检索的LLM客户端
llm_client = OpenAIModelClient(
    api_key="sk-xxxxx",
    base_url="http://xxxxx",
    model="<model_name>",
)

graph_kb = GraphKnowledgeBase(
    config=kb_config,
    vector_store=vector_store,
    embed_model=embed_model,
    llm_client=llm_client,
)

# 通过RetrievalConfig启用智能检索
retrieval_config = RetrievalConfig(
    top_k=5,
    agentic=True,
    use_graph=True,
    graph_expansion=True,
)

results = await graph_kb.retrieve("复杂的多跳问题", config=retrieval_config)
```

在底层，知识库会将其内部检索器包装为 `AgenticRetriever`，执行迭代查询重写和RRF融合。当与 `GraphKnowledgeBase` 配合使用时，图扩展和三元组链接等图特有功能会自动启用，除非通过 RetrievalConfig 显式禁用。

> **说明**：智能检索需要在知识库上配置 `llm_client`。`AgenticRetriever` 本身接受任意 `Retriever` 子类，因此可以与向量检索器、稀疏检索器、混合检索器和图检索器配合使用。如需创建 kb_config、vector_store 和 embed_model，请参考下方完整的知识库使用代码示例。

# 完整的使用知识库代码示例

```python
import asyncio

from openjiuwen.core.retrieval.common.config import (
    EmbeddingConfig,
    KnowledgeBaseConfig,
    RetrievalConfig,
    StoreType,
    VectorStoreConfig,
)
from openjiuwen.core.retrieval.embedding.openai_embedding import OpenAIEmbedding
from openjiuwen.core.retrieval.indexing.indexer.milvus_indexer import MilvusIndexer
from openjiuwen.core.retrieval.indexing.processor.chunker.chunking import TextChunker
from openjiuwen.core.retrieval.indexing.processor.parser.auto_file_parser import AutoFileParser
from openjiuwen.core.retrieval.simple_knowledge_base import SimpleKnowledgeBase
from openjiuwen.core.retrieval.vector_store.milvus_store import MilvusVectorStore


async def create_kb() -> None:
    """创建知识库"""
    # 定义知识库配置
    kb_config = KnowledgeBaseConfig(
        kb_id="test_kb_001",
        index_type="hybrid",  # 支持 vector、bm25、hybrid
        use_graph=False,
        chunk_size=512,
        chunk_overlap=50,
    )

    # 创建向量存储
    # milvus_uri表示Milvus服务的主机地址（默认为http://localhost:19530）, milvus_token为用于身份认证的key（默认为空）
    vector_store_config = VectorStoreConfig(
        store_provider=StoreType.Milvus,
        collection_name=f"kb_{kb_config.kb_id}_chunks",
        distance_metric="cosine",
    )
    milvus_uri = "http://localhost:19530"
    milvus_token = ""
    vector_store = MilvusVectorStore(
        config=vector_store_config,
        milvus_uri=milvus_uri,
        milvus_token=milvus_token,
    )

    # 创建嵌入模型
    # model_name表示使用的embedding模型名, base_url表示请求embedding API的地址, api_key表示密钥, max_retries表示最大重试次数, timeout表示请求超时时间
    embedding_config = EmbeddingConfig(
        model_name="xxxxx",
        api_key="sk-xxxxx",
        base_url="http://xxxxx",
    )

    # You can specify embedding dimension or leave it at default
    embed_model = OpenAIEmbedding(config=embedding_config, max_retries=3, timeout=60, dimension=128)

    # 创建索引管理器（与向量存储共用 VectorStoreConfig）
    indexer = MilvusIndexer(
        config=vector_store_config,
        milvus_uri=milvus_uri,
        milvus_token=milvus_token,
    )

    # 创建文档解析器（自动识别文件格式）
    parser = AutoFileParser()

    # 创建文本分块器
    chunker = TextChunker(
        chunk_size=kb_config.chunk_size,
        chunk_overlap=kb_config.chunk_overlap,
        chunk_unit="token",  # 支持 char 或 token
    )

    # 创建知识库实例
    knowledge_base = SimpleKnowledgeBase(
        config=kb_config,
        vector_store=vector_store,
        embed_model=embed_model,
        parser=parser,
        chunker=chunker,
        index_manager=indexer,
    )

    return knowledge_base


async def add_documents(knowledge_base: SimpleKnowledgeBase) -> None:
    """添加文档"""
    # 准备文档文件路径
    file_paths = [
        "./documents/doc1.pdf",
        "./documents/doc2.txt",
        "./documents/doc3.md",
    ]

    # 解析文件为Document对象列表
    documents = await knowledge_base.parse_files(file_paths)

    # 添加doc id
    for doc_idx, doc in enumerate(documents, 1):
        doc.id_ = f"doc_id_{doc_idx}"

    # 添加文档到知识库（自动分块和构建索引）
    doc_ids = await knowledge_base.add_documents(documents)
    print(f"成功添加 {len(doc_ids)} 个文档，文档ID: {doc_ids}")


async def retrieval(knowledge_base: SimpleKnowledgeBase) -> None:
    # 配置检索参数
    retrieval_config = RetrievalConfig(
        top_k=3,  # 返回前3个结果
        filters=None,  # 元数据过滤条件（可选）
    )

    # 执行检索
    query = "什么是人工智能？"
    results = await knowledge_base.retrieve(query, config=retrieval_config)

    # 打印检索结果
    for i, result in enumerate(results, 1):
        print(f"\n结果 {i}:")
        print(f"  文本: {result.text[:100]}...")
        print(f"  相似度: {result.score:.4f}")
        print(f"  文档ID: {result.doc_id}")
        print(f"  块ID: {result.chunk_id}")
        print(f"  meta: {result.metadata}")


async def delete_document_id(knowledge_base: SimpleKnowledgeBase) -> None:
    doc_ids_to_delete = ["doc_id_1", "doc_id_2"]
    success = await knowledge_base.delete_documents(doc_ids_to_delete)
    print(f"删除结果: {success}")


if __name__ == "__main__":
```
