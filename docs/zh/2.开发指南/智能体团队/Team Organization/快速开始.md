# Team Organization 快速开始

本示例展示如何把两个已激活的 Agent Team 加入同一个 Organization。生产应用通常让 Leader 调用自动注入的 `org_*` 工具；宿主也可以直接调用 Python API 管理组织生命周期。

## 前置条件

1. 按 [AgentTeams 使用指南](../AgentTeams.md) 创建并激活 Team。
2. Owner Team 和待邀请 Team 使用同一个 `TeamDatabase` 实例。
3. 两个 Team 位于同一个 session，且在 `TeamRuntimeManager` 的活动池中。

## 创建并邀请 Team

```python
runtime = team_runtime_manager.organization_runtime_manager

organization = await runtime.create_organization(
    organization_id="product-release",
    owner_team_id="planning-team",
    session_id="session-001",
    display_name="产品发布组织",
    description="由策划、研发和测试团队共同完成发布",
)

organization = await runtime.invite_team(
    organization_id=organization.organization_id,
    inviter_team_id="planning-team",
    target_team_id="engineering-team",
    session_id="session-001",
)
```

`organization_id` 同时用于工作空间路径，必须是安全的单个路径段，不能包含 `/`、`\\`、`..` 或前后空白。只有 Owner Team 可以邀请成员或解散 Organization。一个 Team 不能同时属于两个 Organization。

绑定完成后，Leader 会获得组织管理、任务协作和 Leader Inbox 工具。可以通过提示词让 Owner Leader 建立任务：

```text
创建一个组织根任务“完成产品发布方案”，认领该根任务并使用 HIERARCHICAL 汇总。
把“实现发布接口”创建为子任务，要求 backend 能力并委派给 engineering-team。
完成前检查所有直接子任务均已审核通过。
```

任务协作建议通过 Leader 的 `org_create_task`、`org_claim_task`、`org_update_task` 等工具完成，这样创建者身份、成员资格、能力要求和任务树关系会得到统一校验。需要由外部系统创建 client-originated 根任务的宿主，可在集成层使用 `TeamOrganizationManager.task_pool`；该路径属于宿主集成能力，不建议业务侧绕过 Leader 工具直接操作。

## 查询与解散

Leader 可调用 `org_view_organization` 和 `org_view_tasks` 查询状态。宿主可以直接调用：

```python
current = await runtime.get_organization(
    organization_id="product-release",
    team_id="planning-team",
    session_id="session-001",
)

await runtime.dissolve_organization(
    organization_id="product-release",
    owner_team_id="planning-team",
    session_id="session-001",
)
```

解散操作会解绑成员、停止 Organization 的 Summary Team，并删除该 Organization 的持久化记录。不要把它作为普通任务结束操作；任务完成后 Organization 可以继续复用。
