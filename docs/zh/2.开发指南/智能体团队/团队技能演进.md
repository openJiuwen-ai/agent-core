# 团队技能演进

团队技能演进是 agent-core 提供的多 Agent 协作技能自动化创建和在线演进功能，支持从真实协作上下文中提炼可复用的团队协作模式。

## 核心概念

### Team Skill

团队技能是一种特殊类型的 Skill，包含以下文件结构：

```
skills/<skill-name>/
├── SKILL.md          # 入口文件（YAML frontmatter + Markdown body）
│                      # frontmatter 必须包含 kind: team-skill
├── roles/
│   ├── <role-id>.md  # 每个角色的详细定义
│   └── ...
├── workflow.md       # 工作流描述（任务依赖、并行/串行关系）
├── bind.md           # 约束信息（轮数上限、超时、质量门）
└── evolutions.json   # 演进记录
```

与普通 Skill 不同，Team Skill：

- `kind: team-skill` 标识类型
- `roles` 列表定义角色及其 skills/tools 配置
- 适用于多 Agent 协作场景

### 演进机制

| 模块 | 功能 |
|------|------|
| `TeamSkillCreateRail` | 自动检测协作模式，建议创建团队技能 |
| `TeamSkillRail` | 在线演进 public rail，是 `TeamSkillEvolutionRail` 的兼容 public alias。 |
| `SkillExperienceOptimizer` | 被动信号链路共用的 optimizer，团队场景配置为 `profile="team"`。 |
| `evolution_reviewer` | Agent 判断的主动审核链路使用的专用 subagent，通过 Rail 自有的 `evolve_review_task` 调用。 |
| `ExperienceScorer` | 经验评分和简化维护 |
| `InMemoryTrajectoryRegistry` | 运行时 source/sink，用于发布成员 snapshot 并聚合团队轨迹证据 |
| `TeamTrajectoryAggregator` | 面向存量轨迹的离线/调试聚合工具 |

## 自动创建

### 原理

`TeamSkillCreateRail` 会先等待团队任务完成，再检查本次执行是否 spawn 了足够多的团队成员、且没有使用已有 Team/Swarm Skill。满足这些 gate 后，Rail 注入简短 follow_up 唤起下一轮，并通过系统提示词引导 Agent 判断协作模式是否可复用；如果值得沉淀，必须通过普通回复文本向用户确认，不能使用弹窗式交互工具。

### 配置示例

```python
from openjiuwen.harness.rails import TeamSkillCreateRail
from openjiuwen.harness import create_deep_agent

create_rail = TeamSkillCreateRail(
    skills_dir="/path/to/skills",
    language="cn",
    min_team_members_for_create=2,  # spawn_member >= 2 时触发
)

agent = create_deep_agent(
    model=model_client,
    system_prompt="你是一个团队 leader...",
    tools=team_tools,
    rails=[create_rail],
    enable_task_loop=True,
    workspace="/path/to/workspace",
)
```

### 创建流程

1. Agent 执行协作流程（调用 `build_team`、`spawn_member`、`create_task`）
2. 团队完成回调标记本轮可进入创建检查
3. Rail 检测 `spawn_member` 调用次数达到阈值，且未使用已有 Team/Swarm Skill
4. Rail 通过 `TaskLoopController.enqueue_follow_up()` 注入简短 follow_up，并在下一轮模型调用前注入系统自检提示
5. Agent 判断有复用价值后，通过普通回复文本询问用户是否创建 Team/Swarm Skill
6. 用户确认创建或提供自定义指令
7. Agent 调用 `swarmskill-creator` 或兼容的团队技能创建 Skill
8. 技能根据当前团队上下文生成 Team/Swarm Skill 文件

## 在线演进

### TeamSkillRail 配置

```python
from openjiuwen.agent_evolving.trajectory import InMemoryTrajectoryRegistry
from openjiuwen.harness import create_deep_agent
from openjiuwen.harness.rails import (
    EvolutionInterruptRail,
    EvolutionReviewRuntime,
    TeamSkillRail,
)

trajectory_registry = InMemoryTrajectoryRegistry()
review_runtime = EvolutionReviewRuntime()

team_rail = TeamSkillRail(
    skills_dir="/path/to/skills",
    llm=model_client,
    model="gpt-4",
    language="cn",
    team_id="research-team",
    trajectory_source=trajectory_registry,
    trajectory_sink=trajectory_registry,
    review_runtime=review_runtime,
    signal_trigger=False,      # 如需被动信号生成可显式开启
    review_trigger=True,       # 团队完成后由 Agent 判断
    auto_save=False,           # 生成的记录需要用户审批
    async_evolution=True,      # 异步执行演进
    evolution_total_timeout_secs=600.0,
)
interrupt_rail = EvolutionInterruptRail(
    review_runtime=review_runtime,
    submission_service=team_rail.experience_manager.experience_submission_service,
)

agent = create_deep_agent(
    model=model_client,
    tools=team_tools,
    rails=[interrupt_rail, team_rail],
    skills=["research-team"],  # 加载已有团队技能
)
```

`trajectory_source` 和 `trajectory_sink` 是团队轨迹聚合的运行时接入点。Rail 在 invoke 结束后把 `MemberTrajectorySnapshot` 发布到 sink；`TeamSkillRail` 在被动演进或用户主动演进需要团队级证据时，从 source 读取聚合轨迹。

若要聚合多个成员，需要让所有贡献轨迹证据的 rail 或 agent 都发布到同一个 `trajectory_sink`；`TeamSkillRail` 再通过 `trajectory_source` 读取这个共享 registry。

`MemberTrajectorySnapshot` 只包含发布内容：`team_id`、`session_id`、`member_id`、`member_role`、`trajectory` 和 `recorded_at_ms`。snapshot 新旧判定由 `InMemoryTrajectoryRegistry` 负责：`recorded_at_ms` 更新者优先；时间相同则使用 registry 的接收顺序，后接收者优先。

### 触发时机

| 触发方式 | 触发条件 |
|----------|----------|
| 被动信号触发 | `signal_trigger=True`，且检测到团队完成 |
| 完成态主动审核 | `review_trigger=True`，且检测到团队完成 |
| 用户请求审核 | Host 调用 `request_user_evolution()`，并把返回的 `followup_prompt` 交给主 Agent |

两个开关默认均为 `False`。若同时开启，完成态主动审核优先，本次完成不会再执行被动信号生成。

### 演进路径

#### 1. 被动信号演进

当 `signal_trigger=True` 时，Rail 聚合团队执行证据并检测以下问题：

- **角色配合问题**: 协作断裂、数据未传递
- **约束违反**: 超时、产出格式不合规
- **流程低效**: 重复调用、多余步骤
- **角色能力不足**: 某角色多次失败或产出质量不达标

检测到问题时，Rail 调用共享的 `SkillExperienceOptimizer(profile="team")` 生成经验记录。该链路直接暂存记录，并走下方的记录审批流程。

#### 2. Agent 判断的主动审核

当 `review_trigger=True` 时，团队完成会安排一条简短的自检 follow_up。主 Agent 判断本轮使用过的团队技能是否需要演进；若需要，先调用 `prepare_skill_evolution(user_confirmed=true)`，再把返回的 `evolution_review_ref` 交给 Rail 自有的 `evolve_review_task`。该工具只运行专用 `evolution_reviewer`，在有界审核材料上分析，并通过共享 review runtime 提交演进建议。

主动链路不需要全局 `SubagentRail` 或通用 `task_tool`。

#### 3. 用户请求演进

用户主动提供改进建议：

```python
result = await team_rail.request_user_evolution(
    skill_name="research-team",
    user_intent="增加 reviewer 角色，限制 research 时间不超过 10 分钟",
)
```

`request_user_evolution()` 返回 `agent_prompt` 模式的 `EvolutionRequestResult`。Host 把 `result.followup_prompt` 交给主 Agent；该 prompt 要求执行相同的 `prepare_skill_evolution` → `evolve_review_task` 主动审核序列。当前 Rail 轨迹或聚合后的团队轨迹作为默认证据窗口，`user_intent` 只补充优化方向。

### 被动记录审批流程

1. Rail 生成经验记录并暂存
2. Host UI 展示 `drain_pending_host_events()` 返回的审批事件
3. 用户选择"Accept"或"Reject"
4. 审批时调用 `approve_record(request_id)` 写入 `evolutions.json`

```python
for event in await team_rail.drain_pending_host_events(wait=True):
    meta = event.payload.get("evolution_meta", {})
    if meta.get("event_kind") == "approval":
        await team_rail.approve_record(event.payload["request_id"])
```

主动审核建议通过 `EvolutionInterruptRail` 和审核工具处理，不走这里的被动 `approval_event` 链路。

## 经验管理

### 评分体系

ExperienceScorer 使用三维度加权评分：

| 维度 | 公式 | 权重 |
|------|------|------|
| E (Effectiveness) | Beta(1,1) 贝叶斯平滑 | 0.5 |
| U (Utilization) | `times_used / times_presented` | 0.3 |
| F (Freshness) | 时间衰减 + 版本过期惩罚 | 0.2 |

**综合评分**: `score = 0.5 * E + 0.3 * U + 0.2 * F`

### 简化操作

```python
simplify_result = await team_rail.request_simplify(
    skill_name="research-team",
    user_intent="清理过时经验",
)

if simplify_result.approval_event:
    await team_rail.on_approve_simplify(simplify_result.request_id)

# scorer 生成的清理动作会在审批后执行。
```

| 操作 | 说明 |
|------|------|
| DELETE | 删除低质量经验（score < 阈值） |
| MERGE | 合并相似经验 |
| REFINE | 优化冗长内容 |
| KEEP | 保留高质量经验 |

### 重建流程

```python
prompt = await team_rail.request_rebuild(
    skill_name="research-team",
    user_intent="基于历史经验全面优化",
    min_score=0.5,  # 仅保留 score >= 0.5 的经验
)

# prompt 为重建指令文本，需注入到 Agent 执行
```

重建流程：

1. 归档当前 `SKILL.md` 和 `evolutions.json` 到 `archive/`
2. 筛选高质量演进经验（score >= min_score）
3. 构建重建提示，调用 `teamskill-creator` 技能生成新版本
4. 清空 `evolutions.json`

## 最佳实践

### 何时使用

- 多 Agent 协作场景（`spawn_member >= 2`）
- 需要沉淀协作经验、形成可复用模式
- 团队技能需要持续改进和优化

### 配置建议

| 配置项 | 建议 |
|--------|------|
| `min_team_members_for_create` | 根据团队规模调整，建议 2-3 |
| `auto_save` | 重要演进建议 `False`，确保审批 |
| `async_evolution` | 长任务建议 `True`，避免阻塞 |
| `evolution_total_timeout_secs` | 根据任务复杂度调整，建议 300-900 |

### 定期维护

1. 每周执行 `request_simplify()`，并审批生成的清理动作来清理低质量经验
2. 每月评估是否需要 `request_rebuild()` 重建
3. 重要演进前设置 `auto_save=False` 确保用户审批

### 注意事项

- `TeamSkillCreateRail` 和 `TeamSkillRail` 可同时使用
- `TeamSkillCreateRail` 依赖 `enable_task_loop=True` 的 DeepAgent
- 演进生成的内容需用户审批才能生效
