# A2A Client

`A2AClient` is the openjiuwen wrapper around the A2A SDK Client.
It accepts openjiuwen-style input and converts it to A2A requests.

## Main API

```python
from openjiuwen.extensions.a2a.a2a_client import A2AClient
```

- `A2AClient(card: AgentCard | None = None, polling: bool = False)`
  - Creates a client using an A2A `AgentCard`.
  - `polling` is passed through to the underlying A2A SDK Client configuration.
  - This wrapper completes SDK client initialization during construction.
- `await client.invoke(inputs: dict[str, Any]) -> AgentResult`
  - Sends a request and returns the `AgentResult` corresponding to the first available event.
  - This is consistent with the SDK's `send_message()` iterator model, as the A2A SDK does not have a separate HTTP "invoke" RPC.
- `async for chunk in client.stream(inputs: dict[str, Any])`
  - Sends a streaming request and returns `AgentResult` chunks event by event.
- `await client.stop()`
  - Closes the underlying A2A client connection.

## Input Conventions

The client accepts openjiuwen-style request dictionaries. Common keys include:

- `query`: user input text
- `conversation_id`: the more common session identifier at the openjiuwen Runner layer
- `sessionId`: compatible input format, which will be normalized to the same result session value
- Other metadata fields will be passed through when possible
- `conversation_id` is the preferred upstream session key; `sessionId` is retained only for compatibility
- `task_id` is not created on the client side and is usually generated by the remote A2A service

Requests are first passed to `A2ATransformer.to_a2a_request()` to be converted into A2A requests.

## Output Conventions

Both `invoke()` and `stream()` return openjiuwen `AgentResult`. A2A responses are converted back to openjiuwen data structures via `A2ATransformer.from_a2a_response()`.
The `sessionId` in the returned result will be preferentially backfilled with the `conversation_id` passed in by the caller; `sessionId` is retained only for compatibility.
`invoke()` returns the first available event, while `stream()` returns them event by event.

## Payload and Card Mapping

`A2AClient` relies on two transformation helper classes:

- `A2ATransformer`: responsible for request and response transformation
- `A2AAgentCardAdapter`: responsible for converting local openjiuwen cards to A2A cards

### Request Mapping

| openjiuwen Input Field | A2A Field | Description |
| --- | --- | --- |
| `query` | `message.parts[0].text` | The first text part becomes the user input content. |
| `conversation_id` / `sessionId` | `message.context_id` | The session identifier is normalized and written into the A2A context. |
| Other top-level fields | `send_request.metadata` | Fields other than `query`, `conversation_id`, and `sessionId` are preserved in A2A metadata as much as possible. |
| `metadata` | `send_request.metadata` | If a dict is provided, it is merged into A2A metadata. |

### Response Mapping

| A2A Source Object / Field | openjiuwen `AgentResult` Field | Description |
| --- | --- | --- |
| `Message.task_id` | `task_id` | Retained as the result task ID. |
| `Message.context_id` | `sessionId` | Retained as the result session ID. |
| `Message.parts` | `artifacts[0].parts` | Message content is converted into an artifact named `message`. |
| `Task.id` | `task_id` | Retained as the result task ID. |
| `Task.context_id` | `sessionId` | Retained as the result session ID. |
| `Task.status.state` | `status` | Mapped to openjiuwen's `TaskStatus`. |
| `Task.artifacts` | `artifacts` | Converted artifact by artifact. |
| `TaskStatusUpdateEvent` / `TaskArtifactUpdateEvent` | `AgentResult` | Streaming events are converted into incremental openjiuwen results. |

### AgentCard Mapping

| openjiuwen `AgentCard` Field | A2A `AgentCard` Field | Description |
| --- | --- | --- |
| `name` | `name` | Copied directly. |
| `description` | `description` | Copied directly; if there are input/output parameters, they are appended to the description text. |
| `input_params` | `description` | Serialized and appended as `[input_params] ...`. |
| `output_params` | `description` | Serialized and appended as `[output_params] ...`. |
| `interface_url` | `supported_interfaces[0].url` | Used when `supported_interfaces` is not explicitly passed in. |
| `protocol_binding` | `supported_interfaces[0].protocol_binding` | Defaults to `HTTP+JSON`, can be overridden. |
| `protocol_version` | `supported_interfaces[0].protocol_version` | Defaults to `1.0`, can be overridden. |
| `tenant` | `supported_interfaces[0].tenant` | Retained when provided. |
| `supported_interfaces` | `supported_interfaces` | Explicit interface list takes precedence over `interface_url`. |

### Part Mapping

| openjiuwen `Part` Field | A2A `Part` Field | Description |
| --- | --- | --- |
| `text` | `text` | Copied directly. |
| `raw` | `raw` | Copied directly. |
| `url` | `url` | Copied directly. |
| `data` (dict) | `data.struct_value` | Dicts are serialized as protobuf struct. |
| `data` (other types) | `data.string_value` | Non-dict values are first converted to strings. |
| `filename` | `filename` | Copied directly. |
| `media_type` | `media_type` | Copied directly. |
| `metadata` | `metadata` | Serialized as protobuf struct. |

## Plugin Usage

In runner-based integrations, `A2AClient` is usually not instantiated directly, but accessed through the remote agent protocol:

- `RemoteAgent(protocol=ProtocolEnum.A2A, ...)` resolves to the `A2A` remote client plugin
- `openjiuwen.extensions.a2a` registers the factory to the runner registry
- Using `pip install "openjiuwen[all-a2a]"` or `uv sync --extra all-a2a` installs the A2A SDK dependencies

If you need to use the client directly outside of `RemoteAgent`, you can also manually construct `A2AClient` and pass in an A2A `AgentCard`.

## Direct Protocol Usage

When you want to explicitly create an A2A remote agent, you can write it like this:

```python
from openjiuwen.core.runner.drunner.remote_client.remote_agent import RemoteAgent
from openjiuwen.core.runner.drunner.remote_client.remote_client_config import ProtocolEnum
from openjiuwen.core.single_agent.schema.agent_card import AgentCard

agent = RemoteAgent(
    agent_id="a2a-agent",
    protocol=ProtocolEnum.A2A,
    config={
        "url": "http://127.0.0.1:41241",
        "kwargs": {
            "card": AgentCard(id="a2a-agent", name="a2a-agent"),
            "polling": True,
        },
    },
)
```

The chain is:

`RemoteAgent -> create_remote_client("A2A") -> A2ARemoteClient -> A2AClient -> A2A SDK`

### Parameter Description

| Parameter | Meaning |
| --- | --- |
| `card` | Required in the remote client path; what is passed in here is openjiuwen's `AgentCard`, which will then be converted to an A2A card. |
| `polling` | Optional, defaults to `False`, passed through to A2A SDK Client configuration. |

### Polling Behavior

`polling` controls whether the underlying A2A SDK automatically polls the task after sending a message.

| Setting | Behavior | Return Result |
| --- | --- | --- |
| `polling=True` | The client continuously polls the A2A task after sending the request until it reaches a terminal state. | Usually returns the final result, such as a completed `Message` or `Artifact`. |
| `polling=False` | The client does not automatically poll after sending the request. | Returns a task-related result first; lifecycle management needs to be handled by you. |

If you manually take over the task lifecycle, you can continue to query the task status based on the returned task identifier, or use the SDK's task subscription interface to resubscribe to the task stream.

## Example

```python
from openjiuwen.extensions.a2a.a2a_client import A2AClient

client = A2AClient(card=a2a_agent_card)
result = await client.invoke({"query": "hello", "conversation_id": "conv-1"})
```
